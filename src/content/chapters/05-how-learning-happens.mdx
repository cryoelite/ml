A direct formula can fit a straight line. Many models have no direct solution, so training improves their parameters through repeated updates.

Gradient descent uses the loss to decide how each parameter should change. It moves opposite the gradient, which points toward increasing loss. The learning rate sets the size of each update.

```python run setup title="gradient descent, entire"
import numpy as np, matplotlib.pyplot as plt

rng = np.random.default_rng(0)
n = 60
hours = rng.uniform(0, 10, n)
score = 12 + 7.5 * hours + rng.normal(0, 8, n)

def fit(x, y, lr=0.01, steps=200):
    w, b = 0.0, 0.0                      # start anywhere
    history = []
    for _ in range(steps):
        pred = w * x + b
        resid = pred - y
        grad_w = 2 * (resid * x).mean()  # dL/dw
        grad_b = 2 * resid.mean()        # dL/db
        w -= lr * grad_w                 # step downhill
        b -= lr * grad_b
        history.append((w, b, (resid ** 2).mean()))
    return w, b, np.array(history)

w, b, hist = fit(hours, score)
print(f"learned  w={w:.3f}  b={b:.3f}   (truth 7.5, 12.0)")
print(f"final loss {hist[-1, 2]:.2f}")
```

The loop calculates predictions, measures error, computes gradients, and updates the parameters. This is the basic training process.

After 200 steps, the weight is close to its target, but the bias is not. The next plot shows the path taken by the parameters:

```python run title="watch it descend"
fig, ax = plt.subplots(1, 2, figsize=(8.5, 3))
ax[0].plot(hist[:, 2]); ax[0].set_xlabel("step"); ax[0].set_ylabel("loss")
ax[0].set_title("loss curve"); ax[0].set_yscale("log")
ax[1].plot(hist[:, 0], hist[:, 1], lw=1); ax[1].scatter(7.5, 12, c="crimson", marker="*", s=90)
ax[1].set_xlabel("w"); ax[1].set_ylabel("b"); ax[1].set_title("path through parameter space")
plt.tight_layout()
```

The path moves quickly in one direction and slowly in another. The loss surface is steeper along one parameter than the other. This helps explain why the same learning rate may work well for one parameter and poorly for another.

## Calculate the gradient

For a linear model, mean squared error is the average of squared residuals. A residual is the prediction minus the target. The chain rule gives these gradients:

- For the weight, average twice the residual multiplied by its input.
- For the bias, average twice the residual.

The input affects the weight gradient because changing the slope moves examples with large inputs more. The bias gradient is the average error, so it indicates whether predictions are generally too high or too low.

<Reveal title="Derive the gradients" kind="math" open>

For each example, let the residual be prediction minus target. The loss is the average squared residual. Squaring contributes twice the residual; the prediction changes by the input when the weight changes and by one when the bias changes. Therefore:

$$
\frac{\partial L}{\partial w} = \frac{1}{n}\sum_i 2r_i x_i
\qquad
\frac{\partial L}{\partial b} = \frac{1}{n}\sum_i 2r_i
$$

Some definitions of mean squared error include a factor of one half. That cancels the 2 in both derivatives. It only rescales the gradient, which has the same effect as changing the learning rate.
</Reveal>

## Choose a learning rate

The next example compares three learning rates. A rate that is too small makes slow progress. A rate that is too large can overshoot the low-loss region and cause the loss to rise.

```python run title="three learning rates"
fig, axes = plt.subplots(1, 3, figsize=(9.5, 2.8), sharey=True)
for ax, lr in zip(axes, [0.001, 0.02, 0.045]):
    _, _, h = fit(hours, score, lr=lr, steps=120)
    ax.plot(np.clip(h[:, 2], 1e-2, 1e7))
    ax.set_yscale("log"); ax.set_title(f"lr = {lr}"); ax.set_xlabel("step")
axes[0].set_ylabel("loss (log)")
plt.tight_layout()
```

If the loss becomes NaN, first check the learning rate. A rate that is too high can make parameters grow until calculations overflow. Lower it and try again. Also check for invalid operations such as taking the logarithm of zero.

A learning-rate finder sweeps through values in a short training run:

```python run title="the learning rate finder"
rates, final = [], []
for lr in np.logspace(-4, -1.2, 40):
    _, _, h = fit(hours, score, lr=lr, steps=60)
    rates.append(lr); final.append(min(h[-1, 2], 1e6))

plt.figure(figsize=(5, 3))
plt.plot(rates, final); plt.xscale("log"); plt.yscale("log")
plt.xlabel("learning rate"); plt.ylabel("loss after 60 steps")
plt.axvline(rates[int(np.argmin(final))], ls=":", c="crimson")
plt.tight_layout()
```

Choose a value below the point where the loss starts to rise. The best rate depends on the model, data, and batch size, so measure it rather than assuming one value always works.

## Use batches

The first loop uses all examples for every update. With a large dataset, that can be slow. A batch is the group of examples used for one update. The next example estimates the gradient from a smaller group:

```python run title="the same loop, on batches"
def fit_minibatch(x, y, lr=0.01, epochs=40, batch=8, seed=0):
    rng = np.random.default_rng(seed)
    w, b, hist = 0.0, 0.0, []
    for _ in range(epochs):
        order = rng.permutation(len(x))          # reshuffle every epoch
        for s in range(0, len(x), batch):
            idx = order[s:s + batch]
            xb, yb = x[idx], y[idx]
            resid = (w * xb + b) - yb
            w -= lr * 2 * (resid * xb).mean()
            b -= lr * 2 * resid.mean()
        hist.append(((w * x + b - y) ** 2).mean())
    return w, b, np.array(hist)

w2, b2, h2 = fit_minibatch(hours, score)
print(f"mini-batch: w={w2:.3f} b={b2:.3f}  loss={h2[-1]:.2f}")
print(f"full batch: w={w:.3f} b={b:.3f}  loss={hist[-1,2]:.2f}")
```

A pass over all examples is an **epoch**. A mini-batch uses only part of the data for one update. Its gradient is a noisier estimate of the full-data gradient, but each update costs less. Batch size trades off memory, update time, and gradient noise.

Stochastic gradient descent technically uses one example per update. People often use “SGD” to mean mini-batch training. Batch noise can affect how training proceeds, but it does not guarantee better performance. Check the result on held-out data.

## Momentum and adaptive optimizers

Momentum combines the current gradient with a running average of recent gradients. This can reduce back-and-forth movement when gradients keep changing direction.

```python run title="plain SGD vs momentum"
def fit_general(x, y, lr=0.01, steps=200, beta=0.0):
    w = np.zeros(2)                       # [b, w]
    X = np.column_stack([np.ones(len(x)), x])
    v = np.zeros(2)
    hist = []
    for _ in range(steps):
        g = 2 * X.T @ (X @ w - y) / len(x)
        v = beta * v + (1 - beta) * g     # exponential moving average
        w -= lr * v
        hist.append(((X @ w - y) ** 2).mean())
    return w, np.array(hist)

_, plain    = fit_general(hours, score, beta=0.0)
_, momentum = fit_general(hours, score, beta=0.9)

plt.figure(figsize=(5.2, 3))
plt.plot(plain, label="SGD"); plt.plot(momentum, label="momentum 0.9")
plt.yscale("log"); plt.xlabel("step"); plt.ylabel("loss"); plt.legend()
plt.tight_layout()
```

Adam also tracks the typical size of recent gradients for each parameter. It uses those running averages to scale updates. This can help when parameters have different gradient scales, though no optimizer is best for every problem.

AdamW separates weight decay from Adam's gradient update. This avoids having Adam's per-parameter scaling also change the effect of decay. Use the optimizer recommended for your model, or compare options on validation data.

<Reveal title="Adam and AdamW" kind="math">

Adam tracks an average of recent gradients and an average of their squares. It corrects both for their initial values, then divides the gradient average by the square root of the squared-gradient average. This combines information about the recent direction and size of each parameter's gradients.

AdamW applies weight decay directly to the parameters instead of adding it to the gradient. This keeps decay separate from Adam's adaptive scaling.
</Reveal>

## Train a classifier

The structure of the training loop stays the same for classification. Change the prediction function and loss. For a sigmoid model with binary cross-entropy, the gradient simplifies to input times the difference between predicted probability and target.

```python run title="logistic regression from scratch"
passed = (score > 50).astype(int)

def fit_logistic(x, y, lr=0.5, steps=3000):
    X = np.column_stack([np.ones(len(x)), (x - x.mean()) / x.std()])  # standardised
    w = np.zeros(2)
    for _ in range(steps):
        p = 1 / (1 + np.exp(-(X @ w)))       # sigmoid of the logits
        g = X.T @ (p - y) / len(y)           # <- the same shape as before
        w -= lr * g
    return w, X

w_log, Xs = fit_logistic(hours, passed)
p = 1 / (1 + np.exp(-(Xs @ w_log)))
print(f"training accuracy: {((p > 0.5).astype(int) == passed).mean():.1%}")
```

Feature scales matter. If one feature ranges from 0 to 1 and another from 0 to 1000, their gradients can have very different sizes. Standardizing features—subtracting the mean and dividing by the standard deviation—often makes optimization easier.

## Common training problems

- **The loss becomes NaN.** Lower the learning rate and check for invalid operations.
- **The loss barely changes.** The learning rate may be too low, a gradient may be zero, or the parameters may not be updating. Check the gradients and optimizer step.
- **The loss falls, then rises.** The learning rate may be too high near the minimum. Try reducing it during training.
- **Training loss falls but predictions remain poor.** Check the data, target, baseline, and evaluation split. Low training loss alone does not show that a model will work on new data.

```python run
def fit_reg(x, y, lr=0.01, steps=400, lam=0.0):
    w = b = 0.0
    for _ in range(steps):
        r = (w * x + b) - y
        w -= lr * (2 * (r * x).mean() + 2 * lam * w)
        b -= lr * 2 * r.mean()
    return w, b

for lam in [0.0, 0.1, 1.0, 10.0]:
    w_, b_ = fit_reg(hours, score, lam=lam)
    print(f"lam={lam:5.1f}   w={w_:6.3f}  b={b_:6.3f}")
```

L2 regularization adds a penalty for large weights. Increasing the penalty tends to shrink the weights. This can reduce overfitting, though too much can make the model too simple.

A learning-rate schedule changes the step size during training. Larger steps can help early; smaller steps can help the model settle later. Compare validation results as well as training loss.

```python run
def fit_sched(x, y, lr0=0.02, steps=300, decay=0.0):
    w = b = 0.0
    for t in range(steps):
        lr = lr0 / (1 + decay * t)
        r = (w * x + b) - y
        w -= lr * 2 * (r * x).mean()
        b -= lr * 2 * r.mean()
    return ((w * x + b - y) ** 2).mean()

print(f"constant lr : {fit_sched(hours, score, decay=0.0):.4f}")
print(f"decaying lr : {fit_sched(hours, score, decay=0.02):.4f}")
```

Multiplying a feature by 1000 changes the scale of its gradient. The final example shows how this can make a previously useful learning rate too large. Standardizing inputs makes a shared learning rate more practical.

```python run
scaled = hours * 1000
```
