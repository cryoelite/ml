Model families make different assumptions about the patterns in data. We will fit several to the same task and compare their results. For tabular data, gradient-boosted trees are a useful baseline; other models can be simpler, faster, or more accurate on a particular dataset.

## A common interface

Scikit-learn models often use the same basic interface: fit on examples, then predict on new ones.

```python run setup title="the contract"
import numpy as np
from sklearn.datasets import make_moons
from sklearn.model_selection import train_test_split

X, y = make_moons(n_samples=600, noise=0.28, random_state=0)
X_tr, X_va, y_tr, y_va = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)
print(X_tr.shape, y_tr.shape)
```

That makes it easy to compare model families using the same data split and metric:

```python run title="five families, one loop"
from sklearn.linear_model import LogisticRegression
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import RandomForestClassifier, HistGradientBoostingClassifier
from sklearn.neighbors import KNeighborsClassifier
from sklearn.svm import SVC

models = {
    "logistic regression": LogisticRegression(),
    "decision tree":       DecisionTreeClassifier(max_depth=5, random_state=0),
    "random forest":       RandomForestClassifier(n_estimators=200, random_state=0),
    "gradient boosting":   HistGradientBoostingClassifier(random_state=0),
    "k-nearest (k=15)":    KNeighborsClassifier(n_neighbors=15),
    "SVM (rbf kernel)":    SVC(),
}
fitted = {}
for name, m in models.items():
    m.fit(X_tr, y_tr)
    fitted[name] = m
    print(f"{name:22s} train {m.score(X_tr, y_tr):.3f}   valid {m.score(X_va, y_va):.3f}")
```

The next plot shows how several families represent the same classification task:

```python run title="what each family can express"
import matplotlib.pyplot as plt

xx, yy = np.meshgrid(np.linspace(-1.8, 2.8, 250), np.linspace(-1.3, 1.8, 250))
grid = np.c_[xx.ravel(), yy.ravel()]

fig, axes = plt.subplots(2, 3, figsize=(9.5, 5.2))
for ax, (name, m) in zip(axes.flat, fitted.items()):
    zz = m.predict(grid).reshape(xx.shape)
    ax.contourf(xx, yy, zz, alpha=0.28, cmap="coolwarm", levels=1)
    ax.scatter(X_va[:, 0], X_va[:, 1], c=y_va, s=7, cmap="coolwarm", edgecolors="none")
    ax.set_title(f"{name}\nvalid {m.score(X_va, y_va):.3f}", fontsize=9)
    ax.set_xticks([]); ax.set_yticks([])
plt.tight_layout()
```

The models draw different decision boundaries:

- Logistic regression makes a straight boundary unless you add features.
- A decision tree splits the feature space into rectangular regions.
- A random forest combines many trees and can produce a less blocky boundary.
- An RBF support vector machine can make a smooth nonlinear boundary.
- k-nearest neighbours follows the labels of nearby examples.

These shapes are examples of **inductive bias**: assumptions a model brings before seeing the data. A model whose assumptions match the task may learn from fewer examples. A mismatch can limit performance even with extensive training.

## Decision trees

A decision tree asks a sequence of questions. At each node, it chooses a feature and threshold that separates the labels according to an impurity measure. It then repeats the process for the resulting groups.

```python run title="a tree you can read"
from sklearn.tree import export_text
t = DecisionTreeClassifier(max_depth=2, random_state=0).fit(X_tr, y_tr)
print(export_text(t, feature_names=["x0", "x1"]))
```

A small fitted tree can be printed and inspected. That makes it useful when people need to review the decision rules. A tree is still only an approximation of the data; readable rules do not guarantee that the model is fair or reliable.

Training uses a greedy search. Each split is selected using the current groups, without checking every possible full tree. Exact optimal tree construction is computationally difficult, so practical algorithms use this greedy approach.

Trees usually do not need feature scaling. They can handle nonlinear thresholds, but a tree grown without limits can memorize its training examples.

```python run title="depth is the whole hyperparameter"
for d in [1, 2, 3, 5, 10, None]:
    m = DecisionTreeClassifier(max_depth=d, random_state=0).fit(X_tr, y_tr)
    print(f"max_depth {str(d):4s}   train {m.score(X_tr, y_tr):.3f}   valid {m.score(X_va, y_va):.3f}"
          f"   leaves {m.get_n_leaves():4d}")
```

Limiting tree depth, requiring more examples per leaf, or pruning branches can improve generalization. Choose these settings using validation data.

## Combine trees

A random forest trains many trees on resampled examples and combines their predictions. It also considers random subsets of features at splits. Averaging trees with different errors can reduce variance.

Boosting trains trees in sequence. Each new tree helps correct errors left by earlier trees. This can produce strong results, but adding too many trees can overfit, so validation and early stopping are useful.

```python run title="bagging versus boosting"
for n in [1, 5, 25, 200]:
    rf = RandomForestClassifier(n_estimators=n, random_state=0).fit(X_tr, y_tr)
    gb = HistGradientBoostingClassifier(max_iter=n, random_state=0).fit(X_tr, y_tr)
    print(f"{n:3d} trees   forest {rf.score(X_va, y_va):.3f}    boosting {gb.score(X_va, y_va):.3f}")
```

These methods have different trade-offs. More trees in a random forest usually make its average more stable, at additional compute cost. For boosting, the number of trees and learning rate affect model complexity, so tune them against validation results.

Libraries such as XGBoost, LightGBM, CatBoost, and scikit-learn's histogram-based gradient boosting implement related methods with different engineering choices. Check the library documentation for how each handles missing and categorical values.

## Why trees are often useful for tables

Trees and boosting are strong options for many tabular problems because they can model feature thresholds and interactions without much preprocessing. They handle features with different scales and can work well on datasets that are too small to train a large neural network effectively.

Neural networks can also work with tabular data. Their performance depends on the dataset, architecture, preprocessing, and available data. Compare them when there is a reason to expect their representation learning to help.

A practical starting point is a simple linear model and a tree-based model. Compare both with a baseline using a split that matches the task.

## k-nearest neighbours

k-nearest neighbours (k-NN) stores training examples. To predict, it finds the k closest examples and uses their labels or values.

```python run title="k controls the smoothing"
for k in [1, 5, 25, 100]:
    m = KNeighborsClassifier(n_neighbors=k).fit(X_tr, y_tr)
    print(f"k={k:3d}   train {m.score(X_tr, y_tr):.3f}   valid {m.score(X_va, y_va):.3f}")
```

With k equal to one, a training point's nearest neighbour is itself, so training accuracy is perfect. This shows why training accuracy alone is not enough.

k-NN depends on the distance measure. Scale features so large numeric ranges do not dominate. In very high dimensions, distances often become less informative, and predictions can become expensive because the method compares new examples with stored data.

The same idea appears in vector search. An embedding maps an item to a vector; nearest-neighbour search returns items with nearby vectors. Chapter 12 builds on this idea.

## Support vector machines

A support vector machine (SVM) chooses a boundary that separates classes with a large margin. A kernel lets it model nonlinear boundaries by computing similarities as if the examples had been mapped to a richer feature space.

```python run title="the kernel is the assumption"
for kern in ["linear", "poly", "rbf"]:
    m = SVC(kernel=kern).fit(X_tr, y_tr)
    print(f"{kern:7s} kernel   valid {m.score(X_va, y_va):.3f}")
```

For some kernels, this calculation avoids explicitly creating the richer representation. This is called the kernel trick. An RBF kernel can represent a very flexible boundary, but kernel methods can become expensive as the number of training examples grows. Use them when the dataset size and task suit the implementation.

## Choose a starting model

| Situation | Models to compare |
|---|---|
| Tabular data | linear model, random forest, gradient boosting |
| Need simple rules to inspect | shallow tree or logistic regression |
| Images, audio, or video | pretrained neural network |
| Text | pretrained language model or transformer |
| Very little labelled data | simple models or a pretrained model |
| Similarity and retrieval | embeddings with nearest-neighbour search |

This is a starting list, not a guarantee. Use validation data and a useful baseline to make the decision.

## Feature importance and its limits

Feature importance can help you inspect a model. The next example shows one method for estimating which features the forest used:

```python run title="what the model leaned on"
from sklearn.datasets import load_breast_cancer
d = load_breast_cancer()
rf = RandomForestClassifier(n_estimators=300, random_state=0).fit(d.data, d.target)
order = np.argsort(rf.feature_importances_)[::-1][:6]
for i in order:
    print(f"{d.feature_names[i]:26s} {rf.feature_importances_[i]:.3f}")
```

Built-in importance scores can favour features with many possible split points. Correlated features can also share importance in ways that are hard to interpret.

Importance is not evidence of causation. If support tickets predict customer cancellations, that does not show that tickets cause cancellations. A feature may be associated with the outcome because both reflect another factor.

Permutation importance measures how much a score changes when one feature is shuffled. SHAP values provide another way to describe feature contributions. Both can help explain model behaviour, but neither proves that changing a feature will change the outcome. Causal questions often need an experiment or other causal methods.

The example solution reports baseline performance and inspects important features:

```python run
rng = np.random.default_rng(0)
models = {
    "linear":   LinearRegression(),
    "forest":   RandomForestRegressor(n_estimators=300, random_state=0),
    "boosting": HistGradientBoostingRegressor(random_state=0),
}
print("clean data")
for name, m in models.items():
    m.fit(Xd_tr, yd_tr)
    print(f"  {name:9s} R^2 {m.score(Xd_va, yd_va):.3f}")

noise_tr = rng.normal(size=(len(Xd_tr), 20))
noise_va = rng.normal(size=(len(Xd_va), 20))
Xn_tr = np.hstack([Xd_tr, noise_tr])
Xn_va = np.hstack([Xd_va, noise_va])

print("\n+ 20 columns of pure noise")
for name, m in models.items():
    m.fit(Xn_tr, yd_tr)
    print(f"  {name:9s} R^2 {m.score(Xn_va, yd_va):.3f}")
```

The most complex model does not always win. With a small dataset, a simpler model can be competitive because its assumptions constrain what it can learn.

Noise features can also affect models differently. Tree algorithms consider many candidate splits, so a feature that appears useful by chance can influence the result. Regularization in linear models can reduce the effect of unhelpful coefficients.

Use these results as evidence for this dataset, not as a rule that one model family always wins.
