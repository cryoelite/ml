A numerical estimate changes one parameter at a time and repeats the model calculation. That is too slow for a large network. Backpropagation applies the chain rule from the loss back through the network, calculating all parameter gradients in one backward pass.

## Start with a small function

Begin with a short function built from several operations:

```python run setup title="a tiny composed function"
import numpy as np, matplotlib.pyplot as plt

# f(x) = (3x + 1)^2, decomposed into steps
def forward_verbose(x):
    a = 3 * x        # step 1
    b = a + 1        # step 2
    c = b ** 2       # step 3
    return a, b, c

a, b, c = forward_verbose(2.0)
print(f"x=2  ->  a={a}  b={b}  c={c}")
```

We want to know how the output changes when the input changes. The chain rule answers this by multiplying the local derivatives, working backward through the operations.

```python run title="the backward pass"
x = 2.0
a, b, c = forward_verbose(x)

dc_dc = 1.0            # trivially, c changes 1:1 with itself
dc_db = dc_dc * 2 * b  # c = b^2      =>  dc/db = 2b
dc_da = dc_db * 1      # b = a + 1    =>  db/da = 1
dc_dx = dc_da * 3      # a = 3x       =>  da/dx = 3

print(f"backprop : dc/dx = {dc_dx}")
print(f"analytic : dc/dx = {2 * (3 * x + 1) * 3}")
print(f"numeric  : dc/dx = {(forward_verbose(x + 1e-6)[2] - forward_verbose(x - 1e-6)[2]) / 2e-6:.6f}")
```

Each operation needs only its own derivative and the gradient arriving from the next operation. It multiplies them and passes the result back. The gradient is the rate of change of the loss with respect to a value in the computation.

## Why backpropagation is efficient

A forward pass computes each intermediate value once. A backward pass visits the same operations in reverse order and computes the gradients. For many models, calculating all gradients costs about as much as a small number of forward passes, rather than one or more passes for every parameter.

The direction matters. In machine learning, a model can have millions or billions of parameters, while the loss is one scalar. Reverse-mode differentiation efficiently computes the gradient of that one output with respect to many inputs. Forward-mode differentiation is often useful when there are few inputs and many outputs.

## Compute gradients for a network

The network from the previous chapter has a linear layer, a ReLU activation, another linear layer, and a sigmoid output. We use binary cross-entropy as its loss.

For the output layer, the sigmoid derivative and cross-entropy derivative simplify together. The gradient with respect to the output score is the predicted probability minus the target, averaged over the batch.

From there, compute the gradients for the output weights and bias. Pass the error backward through the weights using their transpose. Multiply by a mask for the ReLU, then compute the gradients for the first layer.

<Reveal title="The gradients for each layer" kind="math" open>

For a batch of n examples, let the output error be prediction minus target. With sigmoid and binary cross-entropy, this is the gradient with respect to the output score, divided by n.

For a dense layer, the weight gradient is the layer input transposed times the incoming error. The bias gradient sums the incoming error across the batch. The error passed to the previous layer is the incoming error multiplied by the transpose of the weights.

For ReLU, multiply by a mask that is 1 where the input was positive and 0 elsewhere. Apply the same dense-layer rules to the earlier layer.

The pattern repeats for each layer. Broadcasting a bias forward means summing its gradient across the batch backward.

## Implement the backward pass

The next example puts the forward pass and backward pass together:

```python run title="forward and backward, twenty lines"
from sklearn.datasets import make_moons
from sklearn.model_selection import train_test_split

X, y = make_moons(n_samples=800, noise=0.22, random_state=0)
X = (X - X.mean(0)) / X.std(0)
X_tr, X_va, y_tr, y_va = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)

def init(n_in, n_hidden, n_out, seed=0):
    rng = np.random.default_rng(seed)
    return {"W1": rng.normal(0, np.sqrt(2 / n_in), (n_in, n_hidden)), "b1": np.zeros(n_hidden),
            "W2": rng.normal(0, np.sqrt(2 / n_hidden), (n_hidden, n_out)), "b2": np.zeros(n_out)}

def forward(p, X):
    z1 = X @ p["W1"] + p["b1"]
    a1 = np.maximum(0, z1)
    z2 = a1 @ p["W2"] + p["b2"]
    y_hat = 1 / (1 + np.exp(-z2))
    return y_hat, {"z1": z1, "a1": a1, "z2": z2}   # cache what backward needs

def backward(p, cache, X, y, y_hat):
    n = len(y)
    d2 = (y_hat - y.reshape(-1, 1)) / n            # step 1  (n, 1)
    gW2 = cache["a1"].T @ d2                       # step 2  (h, 1)
    gb2 = d2.sum(0)
    da1 = d2 @ p["W2"].T                           # step 3  (n, h)
    d1  = da1 * (cache["z1"] > 0)                  # step 4  (n, h)
    gW1 = X.T @ d1                                 # step 5  (2, h)
    gb1 = d1.sum(0)
    return {"W1": gW1, "b1": gb1, "W2": gW2, "b2": gb2}

p = init(2, 16, 1)
y_hat, cache = forward(p, X_tr)
grads = backward(p, cache, X_tr, y_tr, y_hat)
{k: v.shape for k, v in grads.items()}
```

The intermediate values from the forward pass are saved in a cache because the backward pass uses them. This is why training needs more memory than prediction: the model keeps intermediate activations until it has computed the gradients.

Check that each gradient has the same shape as the parameter it updates. A mismatch often points to a missing transpose or an incorrect reduction axis.

## Check the gradients

A gradient check compares the backpropagation result with a numerical estimate for a small model:

```python run title="the check every framework's tests do"
def loss_of(p, X, y):
    y_hat, _ = forward(p, X)
    y_hat = np.clip(y_hat.ravel(), 1e-9, 1 - 1e-9)
    return -(y * np.log(y_hat) + (1 - y) * np.log(1 - y_hat)).mean()

def numerical(p, X, y, key, idx, eps=1e-6):
    orig = p[key][idx]
    p[key][idx] = orig + eps; hi = loss_of(p, X, y)
    p[key][idx] = orig - eps; lo = loss_of(p, X, y)
    p[key][idx] = orig
    return (hi - lo) / (2 * eps)

Xs, ys = X_tr[:50], y_tr[:50]
y_hat, cache = forward(p, Xs)
analytic = backward(p, cache, Xs, ys, y_hat)

print(f"{'param':6s} {'index':8s} {'backprop':>12s} {'numeric':>12s} {'rel err':>10s}")
rng = np.random.default_rng(0)
worst = 0.0
for key in ["W1", "b1", "W2", "b2"]:
    for _ in range(3):
        idx = tuple(int(rng.integers(0, s)) for s in p[key].shape)
        an, nu = analytic[key][idx], numerical(p, Xs, ys, key, idx)
        rel = abs(an - nu) / max(abs(an) + abs(nu), 1e-12)
        worst = max(worst, rel)
        print(f"{key:6s} {str(idx):8s} {an:12.8f} {nu:12.8f} {rel:10.2e}")
print(f"\nworst relative error: {worst:.2e}   {'PASS' if worst < 1e-5 else 'FAIL'}")
```

A small relative error suggests the two calculations agree. A large error usually means the implementation has a bug. Check the transposes, batch averaging, and axes used to sum bias gradients.

Gradient checks are useful when writing a custom layer or backward pass. They are too slow for routine training, so run them on a small sample and remove them from the training loop.

## Train with backpropagation

Now use the backward pass in the training loop:

```python run title="the real training loop"
def fit(hidden=32, steps=4000, lr=0.5, seed=0):
    p = init(2, hidden, 1, seed)
    hist = []
    for _ in range(steps):
        y_hat, cache = forward(p, X_tr)
        g = backward(p, cache, X_tr, y_tr, y_hat)
        for k in p:
            p[k] -= lr * g[k]
        hist.append(loss_of(p, X_tr, y_tr))
    return p, np.array(hist)

import time
t = time.perf_counter()
p, hist = fit()
dt = time.perf_counter() - t

acc = ((forward(p, X_va)[0].ravel() > 0.5).astype(int) == y_va).mean()
print(f"4000 steps in {dt:.2f}s   final loss {hist[-1]:.4f}   validation accuracy {acc:.3f}")
```

Compare its speed with numerical differentiation:

```python run title="how much faster, exactly"
def numerical_all(p, X, y, eps=1e-5):
    grads = {}
    for key, mat in p.items():
        g = np.zeros_like(mat)
        for idx in np.ndindex(mat.shape):
            o = mat[idx]
            mat[idx] = o + eps; hi = loss_of(p, X, y)
            mat[idx] = o - eps; lo = loss_of(p, X, y)
            mat[idx] = o
            g[idx] = (hi - lo) / (2 * eps)
        grads[key] = g
    return grads

q = init(2, 32, 1)
n_params = sum(v.size for v in q.values())

t = time.perf_counter()
yh, ca = forward(q, X_tr); backward(q, ca, X_tr, y_tr, yh)
back_ms = (time.perf_counter() - t) * 1000

t = time.perf_counter()
numerical_all(q, X_tr, y_tr)
num_ms = (time.perf_counter() - t) * 1000

print(f"{n_params} parameters, {len(X_tr)} examples")
print(f"  backpropagation : {back_ms:8.2f} ms")
print(f"  numerical       : {num_ms:8.2f} ms   ({num_ms / back_ms:.0f}x slower)")
```

The gap grows with the number of parameters because numerical differentiation repeats the forward pass for each parameter. Backpropagation shares work across parameters.

The trained network's predictions are shown here:

```python run title="the result"
xx, yy = np.meshgrid(np.linspace(-2.2, 2.4, 240), np.linspace(-2.4, 2.4, 240))
zz = forward(p, np.c_[xx.ravel(), yy.ravel()])[0].reshape(xx.shape)

fig, ax = plt.subplots(1, 2, figsize=(8.8, 3.2))
ax[0].plot(hist); ax[0].set_yscale("log"); ax[0].set_xlabel("step"); ax[0].set_ylabel("loss")
ax[1].contourf(xx, yy, zz, levels=24, cmap="coolwarm", alpha=.75)
ax[1].contour(xx, yy, zz, levels=[0.5], colors="k", linewidths=1)
ax[1].scatter(X_va[:, 0], X_va[:, 1], c=y_va, s=8, cmap="coolwarm", edgecolors="none")
ax[1].set_xticks([]); ax[1].set_yticks([]); ax[1].set_title(f"validation accuracy {acc:.3f}")
plt.tight_layout()
```

## Vanishing and exploding gradients

As gradients pass through many layers, repeated multiplication can make them very small or very large.

**Vanishing gradients** become too small for early layers to learn effectively. Sigmoid activations can contribute because their derivatives are usually below one. ReLU passes a gradient of one for positive inputs, but passes zero for negative inputs. Initialization, normalization, and residual connections also affect gradient flow.

**Exploding gradients** grow too large and can make updates unstable. Gradient clipping limits the size of an update when the gradient norm exceeds a chosen threshold.

```python run title="both failure modes, measured"
for name, act, dact in [("sigmoid", lambda z: 1/(1+np.exp(-z)), lambda a: a*(1-a)),
                        ("relu",    lambda z: np.maximum(0,z),  lambda a: (a>0).astype(float))]:
    rng = np.random.default_rng(0)
    a = rng.normal(size=(256, 64))
    Ws = [rng.normal(0, np.sqrt(2/64), (64, 64)) for _ in range(30)]
    caches = []
    for W in Ws:
        a = act(a @ W); caches.append(a)
    g = np.ones_like(a)
    norms = []
    for W, c in zip(reversed(Ws), reversed(caches)):
        g = (g * dact(c)) @ W.T
        norms.append(np.abs(g).mean())
    print(f"{name:8s} gradient magnitude  layer 30 -> {norms[0]:.3e}   layer 1 -> {norms[-1]:.3e}"
          f"   ratio {norms[-1]/norms[0]:.2e}")
```

The example measures how the gradient changes with depth. These patterns depend on the architecture and initialization; the experiment illustrates a mechanism rather than a universal result.

PyTorch accumulates gradients by default. If a training loop omits the step that clears old gradients, each update uses their sum. In the next chapter, we will see how the standard training loop handles this.

```python run
# 1. The missing /n
def backward_buggy(p, cache, X, y, y_hat):
    d2 = (y_hat - y.reshape(-1, 1))                # <- no / n
    gW2 = cache["a1"].T @ d2; gb2 = d2.sum(0)
    d1 = (d2 @ p["W2"].T) * (cache["z1"] > 0)
    return {"W1": X.T @ d1, "b1": d1.sum(0), "W2": gW2, "b2": gb2}

y_hat, cache = forward(p, Xs)
good = backward(p, cache, Xs, ys, y_hat)["W1"]
bad  = backward_buggy(p, cache, Xs, ys, y_hat)["W1"]
print(f"ratio bad/good = {(bad / good).mean():.1f}   (= n = {len(ys)})")
```

Removing the average makes gradients too large by a factor equal to the batch size. The model may still appear to train if the learning rate compensates for it, but changing the batch size can then change the effective step substantially. A gradient check finds the scaling error directly.

```python run
# 2. tanh
def fit_tanh(hidden=32, steps=4000, lr=0.5, seed=0):
    p = init(2, hidden, 1, seed); hist = []
    for _ in range(steps):
        z1 = X_tr @ p["W1"] + p["b1"]; a1 = np.tanh(z1)
        z2 = a1 @ p["W2"] + p["b2"];   yh = 1 / (1 + np.exp(-z2))
        d2 = (yh - y_tr.reshape(-1, 1)) / len(y_tr)
        d1 = (d2 @ p["W2"].T) * (1 - a1 ** 2)
        p["W2"] -= lr * a1.T @ d2; p["b2"] -= lr * d2.sum(0)
        p["W1"] -= lr * X_tr.T @ d1; p["b1"] -= lr * d1.sum(0)
        yc = np.clip(yh.ravel(), 1e-9, 1-1e-9)
        hist.append(-(y_tr*np.log(yc) + (1-y_tr)*np.log(1-yc)).mean())
    return p, np.array(hist)

p_t, hist_t = fit_tanh()
plt.figure(figsize=(5, 3))
plt.plot(hist, label="relu"); plt.plot(hist_t, label="tanh")
plt.yscale("log"); plt.xlabel("step"); plt.ylabel("loss"); plt.legend()
plt.tight_layout()
print(f"relu final {hist[-1]:.4f}   tanh final {hist_t[-1]:.4f}")
```

Tanh can work well in a shallow network. Its gradient becomes small for large positive or negative inputs, which can slow learning in deeper networks. Compare the loss curves rather than assuming one activation always wins.

For an additional layer, repeat the same pattern: calculate the layer's weight and bias gradients, send the error through the transposed weights, and apply the activation derivative. Check each gradient before training.
