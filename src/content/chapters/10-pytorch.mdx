## Tensors and devices

A PyTorch tensor is a multidimensional array. It also records which device stores it and, when needed, how it was computed.

```python run local title="familiar, with additions"
import torch
import numpy as np

t = torch.arange(6.).reshape(2, 3)
print(t)
print(f"shape {tuple(t.shape)}  dtype {t.dtype}  device {t.device}  grad {t.requires_grad}")
```

Most array operations from NumPy have PyTorch equivalents, including broadcasting and matrix multiplication. PyTorch commonly uses float32 values. A tensor made from whole-number Python values is usually an integer tensor, so specify a floating-point value or dtype when needed.

```python run local title="the vocabulary differs slightly"
a = torch.randn(4, 5)
print("numpy  a.reshape(-1)   ->  torch  a.view(-1)   ", tuple(a.view(-1).shape))
print("numpy  a.sum(axis=0)   ->  torch  a.sum(dim=0) ", tuple(a.sum(dim=0).shape))
print("numpy  np.concatenate  ->  torch  torch.cat    ", tuple(torch.cat([a, a]).shape))
print("shares memory with numpy:", np.shares_memory(a.numpy(), a.numpy()))
```

Some PyTorch operations use different names from NumPy. For example, an axis is called a dimension. A tensor created from a NumPy array can share its memory with that array, so changing one may change the other.

## Use automatic differentiation

PyTorch records operations on tensors that require gradients. Calling backward on a scalar loss walks this record in reverse and calculates gradients.

```python run local title="the tape"
x = torch.tensor(3.0, requires_grad=True)
y = x ** 2 + 5 * x
y.backward()
print(f"y = x^2 + 5x  at x=3  ->  dy/dx = {x.grad.item()}   (analytically 2*3 + 5 = 11)")
```

We can compare those gradients with the ones derived by hand:

```python run local title="your network's gradients, checked against yesterday's"
torch.manual_seed(0)
X = torch.randn(50, 2)
y = (X[:, 0] * X[:, 1] > 0).float()

W1 = torch.randn(2, 8, requires_grad=True)
b1 = torch.zeros(8, requires_grad=True)
W2 = torch.randn(8, 1, requires_grad=True)
b2 = torch.zeros(1, requires_grad=True)

a1 = torch.relu(X @ W1 + b1)
p  = torch.sigmoid(a1 @ W2 + b2).squeeze()
loss = torch.nn.functional.binary_cross_entropy(p, y)
loss.backward()

# The same expression you derived in step 2 of chapter 9:
manual_gW2 = a1.T @ ((p - y).unsqueeze(1) / len(y))
print("autograd matches the hand derivation:",
      torch.allclose(W2.grad, manual_gW2, atol=1e-6))
```

The results should agree within floating-point tolerance. Automatic differentiation is useful because it calculates gradients for the graph you define, including models whose derivatives would be tedious to derive by hand.

## Define a model with nn.Module

A neural-network module groups layers and parameters:

```python run local setup title="the same network, declared"
import torch.nn as nn

class Net(nn.Module):
    def __init__(self, n_in=2, hidden=32, n_out=1):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(n_in, hidden),
            nn.ReLU(),
            nn.Linear(hidden, n_out),
        )
    def forward(self, x):
        return self.net(x)          # logits, not probabilities — see below

model = Net()
print(model)
print("parameters:", sum(p.numel() for p in model.parameters()))
```

A module registers layers assigned to its attributes. This lets PyTorch find parameters, move them between devices, and save their values.

A linear layer with a inputs and b outputs stores a weight matrix and a bias vector. It computes a linear transformation of the input.

For classification, the model usually returns raw scores called logits. Use a loss function designed for logits, such as binary cross-entropy with logits or cross-entropy for multiple classes. These loss functions apply the required probability transformation in a numerically stable way. Apply sigmoid or softmax when you need probabilities for display or a later decision.

## Write a training loop

The standard loop has four main steps: clear old gradients, calculate predictions and loss, compute gradients, and update parameters.

```python run local setup title="every PyTorch script you will ever read"
from sklearn.datasets import make_moons
from sklearn.model_selection import train_test_split

Xn, yn = make_moons(n_samples=2000, noise=0.22, random_state=0)
Xn = (Xn - Xn.mean(0)) / Xn.std(0)
Xtr, Xva, ytr, yva = train_test_split(Xn, yn, test_size=0.25, random_state=0, stratify=yn)

Xtr = torch.tensor(Xtr, dtype=torch.float32); ytr = torch.tensor(ytr, dtype=torch.float32)
Xva = torch.tensor(Xva, dtype=torch.float32); yva = torch.tensor(yva, dtype=torch.float32)

torch.manual_seed(0)
model = Net()
loss_fn = nn.BCEWithLogitsLoss()
opt = torch.optim.AdamW(model.parameters(), lr=1e-2)

for epoch in range(300):
    model.train()
    opt.zero_grad()                       # 1. clear last step's gradients
    logits = model(Xtr).squeeze()         # 2. forward
    loss = loss_fn(logits, ytr)           # 3. score
    loss.backward()                       # 4. backward
    opt.step()                            # 5. update

    if epoch % 100 == 99:
        model.eval()
        with torch.no_grad():
            acc = ((model(Xva).squeeze() > 0).float() == yva).float().mean()
        print(f"epoch {epoch+1:3d}   loss {loss.item():.4f}   valid acc {acc:.3f}")
```

zero_grad clears gradients from the previous update. PyTorch accumulates gradients by default, which is useful when intentionally combining several backward passes. For ordinary training, clear them before each update.

model.train() and model.eval() select training or evaluation behaviour for layers such as dropout and batch normalization. Use a no-gradient context for evaluation to save memory and computation.

## Load data in batches

A dataset provides examples. A data loader groups them into batches and can shuffle the order.

```python run local title="Dataset and DataLoader"
from torch.utils.data import TensorDataset, DataLoader

train_dl = DataLoader(TensorDataset(Xtr, ytr), batch_size=64, shuffle=True)

torch.manual_seed(0)
model = Net()
opt = torch.optim.AdamW(model.parameters(), lr=1e-2)

for epoch in range(20):
    model.train()
    for xb, yb in train_dl:                      # <- the only change
        opt.zero_grad()
        loss_fn(model(xb).squeeze(), yb).backward()
        opt.step()

model.eval()
with torch.no_grad():
    acc = ((model(Xva).squeeze() > 0).float() == yva).float().mean()
print(f"mini-batch training, valid acc {acc:.3f}")
```

This separates how data is stored from how training reads it. The same loader can supply batches from different dataset implementations.

## Choose a compute device

Tensors and model parameters must be on compatible devices. Choose a device once, move the model and batches there, and check where they are stored.

```python run local title="pick the device once"
def best_device():
    if torch.cuda.is_available():
        return torch.device("cuda")
    if torch.backends.mps.is_available():
        return torch.device("mps")          # Apple Silicon GPU
    return torch.device("cpu")

dev = best_device()
print("using:", dev)

m = Net().to(dev)
x = torch.randn(256, 2, device=dev)
print("forward on device:", tuple(m(x).shape), m(x).device)
```

A GPU or Apple accelerator can speed up large operations. For a small model, copying data and launching accelerator work may cost more than the calculation itself. Measure performance on your task.

## What PyTorch handles

PyTorch handles tensor operations, automatic differentiation, modules, optimizers, and many common data-loading tasks.

```python run local title="the honest accounting"

print("PyTorch version          : ~11 lines")
print()
for item in [
    "autograd that is correct for ANY graph, not just the one you derived",
    "GPU/MPS execution with a one-word change",
    "fused, tested, numerically-stable loss functions",
    "optimisers you would otherwise reimplement (AdamW, schedulers)",
    "a data pipeline with parallel prefetch",
    "an ecosystem of pretrained weights",
]:
    print(" *", item)
```

A library saves time and reduces repetitive code. It does not decide whether the data, loss, split, or model suits the problem. If training behaves unexpectedly, knowledge of the underlying operations helps you find the cause.

## Common bugs

The next cell summarizes errors that often appear in PyTorch code:

```python run local title="the five-minute reference"
# 1. integer tensor where a float was expected
try:
    nn.Linear(3, 1)(torch.tensor([[1, 2, 3]]))
except Exception as e:
    print("1.", type(e).__name__, "->", str(e)[:88])

# 2. calling backward twice on the same graph
z = torch.tensor(2.0, requires_grad=True) ** 2
z.backward()
try:
    z.backward()
except Exception as e:
    print("2.", type(e).__name__, "->", str(e)[:88])

# 3. the silent one: a shape mismatch that broadcasts instead of failing
pred = torch.randn(8, 1)      # model output
targ = torch.randn(8)         # labels
print("3. (pred - targ).shape =", tuple((pred - targ).shape), "  <- should be (8,), got 8x8")
```

1. **Wrong dtype.** A tensor built from integers may not work with a layer expecting floating-point values.
2. **Backward called twice on a freed graph.** PyTorch releases the computation graph after backward by default. Reuse requires rebuilding the forward pass or intentionally retaining the graph.
3. **Shape mismatch that broadcasts.** Model outputs shaped (n, 1) and labels shaped (n,) can combine into an (n, n) result. Match the shapes explicitly and inspect them before computing the loss.
4. **Gradients not cleared.** Old gradients are added to new ones, which changes the update.
5. **Model left in training mode during evaluation.** Dropout remains active and batch normalization may use batch statistics.

The following experiments show the effect of accumulating gradients and of dropout in training and evaluation modes:

```python run local
# 3. Life without zero_grad
torch.manual_seed(0)
m = Net(); o = torch.optim.SGD(m.parameters(), lr=0.01)
for epoch in range(6):
    # o.zero_grad()   <- deliberately missing
    loss = loss_fn(m(Xtr).squeeze(), ytr)
    loss.backward()
    norm = sum(p.grad.norm().item() ** 2 for p in m.parameters()) ** 0.5
    o.step()
    print(f"epoch {epoch}  loss {loss.item():.4f}  grad norm {norm:8.3f}")
```

When gradients are not cleared, their norm grows as each batch adds to the previous values. That can make the effective update too large and destabilize training.

```python run local
# 4. Dropout behaves differently in train() and eval()
class Dropped(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(2, 32), nn.ReLU(),
                                 nn.Dropout(0.3), nn.Linear(32, 1))
    def forward(self, x): return self.net(x)

torch.manual_seed(0)
d = Dropped(); o = torch.optim.AdamW(d.parameters(), lr=1e-2)
for _ in range(300):
    d.train(); o.zero_grad()
    loss_fn(d(Xtr).squeeze(), ytr).backward(); o.step()

d.train()
with torch.no_grad():
    a = [round((((d(Xva).squeeze() > 0).float() == yva).float().mean()).item(), 4) for _ in range(3)]
d.eval()
with torch.no_grad():
    b = round((((d(Xva).squeeze() > 0).float() == yva).float().mean()).item(), 4)
print("train() mode, three runs:", a, " <- different each time")
print("eval()  mode:            ", b, " <- deterministic")
```

Dropout randomly removes some activations during training. In evaluation mode it is disabled, so predictions are stable. Always switch to evaluation mode when measuring a model.
