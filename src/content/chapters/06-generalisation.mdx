A model can fit its training examples and still make poor predictions on new ones. A lookup table is an extreme example: it can return the stored answer for every training input and has no useful answer for inputs it has not seen.

```
def predict(x):
    return lookup_table[x]
```

A training score measures fit to training data. To estimate performance on new data, evaluate on examples that were not used to fit the model. This chapter shows how to make that estimate useful.

## See overfitting

The next dataset contains a small number of noisy points. We know the curve that generated them, but a real project would only give us the points.

```python run setup title="a small, noisy dataset"
import numpy as np, matplotlib.pyplot as plt
from sklearn.preprocessing import PolynomialFeatures
from sklearn.linear_model import LinearRegression
from sklearn.pipeline import make_pipeline

rng = np.random.default_rng(3)
n = 22
x = np.sort(rng.uniform(0, 1, n))
y_true = lambda t: np.sin(2.2 * np.pi * t)
y = y_true(x) + rng.normal(0, 0.28, n)

plt.figure(figsize=(5, 3))
grid = np.linspace(0, 1, 300)
plt.plot(grid, y_true(grid), "k--", lw=1, label="truth")
plt.scatter(x, y, s=22, label="observed (noisy)")
plt.legend(); plt.tight_layout()
```

Fit polynomials with different degrees. A higher degree can follow more detail in the training data.

```python run title="three degrees of freedom"
fig, axes = plt.subplots(1, 3, figsize=(9.5, 2.9), sharey=True)
for ax, deg in zip(axes, [1, 4, 18]):
    model = make_pipeline(PolynomialFeatures(deg), LinearRegression())
    model.fit(x.reshape(-1, 1), y)
    ax.plot(grid, y_true(grid), "k--", lw=1)
    ax.plot(grid, model.predict(grid.reshape(-1, 1)), c="crimson")
    ax.scatter(x, y, s=16)
    ax.set_ylim(-2.2, 2.2); ax.set_title(f"degree {deg}")
plt.tight_layout()
```

The straight line underfits: it is too simple to match the curve. The high-degree polynomial overfits: it follows both the underlying pattern and much of the noise. The middle-degree model balances the two.

```python run title="training error is not the criterion"
for deg in [1, 4, 9, 18]:
    m = make_pipeline(PolynomialFeatures(deg), LinearRegression()).fit(x.reshape(-1, 1), y)
    train = ((m.predict(x.reshape(-1, 1)) - y) ** 2).mean()
    true  = ((m.predict(grid.reshape(-1, 1)) - y_true(grid)) ** 2).mean()
    print(f"degree {deg:2d}   train MSE {train:8.4f}   true MSE {true:10.4f}")
```

Training error keeps falling as the model becomes more flexible. Error on the underlying curve falls at first, then rises. In real work we do not know the true curve, so we need a separate set of data to estimate performance.

Overfitting happens when a model captures details that do not repeat beyond the training data. Flexible models can fit both useful patterns and random variation.

## Use training, validation, and test data

The previous example compared predictions with the known generating curve. Real datasets do not reveal that true answer. Instead, set some labelled examples aside before training.

```python run title="the split"
from sklearn.model_selection import train_test_split

X = x.reshape(-1, 1)
X_tr, X_va, y_tr, y_va = train_test_split(X, y, test_size=0.35, random_state=0)

print(f"{len(X_tr)} train, {len(X_va)} validation")
for deg in [1, 4, 9, 18]:
    m = make_pipeline(PolynomialFeatures(deg), LinearRegression()).fit(X_tr, y_tr)
    tr = ((m.predict(X_tr) - y_tr) ** 2).mean()
    va = ((m.predict(X_va) - y_va) ** 2).mean()
    print(f"degree {deg:2d}   train {tr:7.4f}   valid {va:10.4f}")
```

A validation set stands in for new data. Use it to compare models, choose hyperparameters, or decide when to stop training. Keep a separate test set for a final evaluation after those decisions are complete.

| Split | How it is used |
|---|---|
| Training | Fit the model parameters |
| Validation | Choose models and settings |
| Test | Estimate final performance once, after choices are complete |

Repeatedly checking the same validation set can lead you to overfit your choices to it. The test set helps catch that. If you use the test set to make more decisions, it becomes another validation set.

## Match the split to the real task

A random split is appropriate when examples are independent and deployment will look similar. It can give an overly optimistic score when examples are related or ordered in time.

```python run title="random splits lie about time series"
from sklearn.linear_model import Ridge

t = np.arange(300)
series = np.cumsum(rng.normal(0, 1, 300)) + 0.05 * t     # a random walk with drift
feats  = np.column_stack([np.roll(series, k) for k in (1, 2, 3)])[5:]
target = series[5:]

# A: shuffled split — leaks the future into the past
Xa_tr, Xa_va, ya_tr, ya_va = train_test_split(feats, target, test_size=0.3, random_state=0)
a = Ridge().fit(Xa_tr, ya_tr).score(Xa_va, ya_va)

# B: honest split — train on the past, validate on the future
cut = int(len(feats) * 0.7)
b = Ridge().fit(feats[:cut], target[:cut]).score(feats[cut:], target[cut:])

print(f"random split  R^2 = {a:.3f}   <- flattering")
print(f"time-based    R^2 = {b:.3f}   <- what you would actually get")
```

With a random split, a model may train on later dates and be evaluated on an earlier date. For a future forecast, that is the wrong direction. Split by time so training data comes before validation data.

Use the same principle for other groups:

- If several rows belong to one person or customer, keep that person in only one split.
- If several images come from one session, split by session.
- For a time series, train on the past and validate on a later period.
- For a competition, match the split to the intended evaluation.

A useful validation set resembles the conditions under which the model will be used. Decide on the split before comparing many models.

The validation set should also be large enough for a stable estimate. With 200 examples, one changed prediction shifts accuracy by half a percent. Avoid treating tiny differences as meaningful. Fix the random seed when you need to compare runs with the same split.

## Use cross-validation

A single split can be noisy, especially with a small dataset. K-fold cross-validation divides the data into k parts, trains k models, and evaluates each model on a different held-out part.

```python run title="5-fold"
from sklearn.model_selection import cross_val_score

for deg in [1, 4, 9, 18]:
    m = make_pipeline(PolynomialFeatures(deg), LinearRegression())
    scores = -cross_val_score(m, X, y, cv=5, scoring="neg_mean_squared_error")
    print(f"degree {deg:2d}   MSE {scores.mean():9.4f}  ± {scores.std():7.4f}")
```

Compare both the average score and its variation across folds. If the variation is as large as the difference between two models, the data may not support a reliable choice between them.

Cross-validation is useful when data is limited and training is affordable. It can be too expensive for very large models.

## Reduce overfitting

Several tools can help:

1. **Get more representative data.** More examples can help the model distinguish a lasting pattern from noise.
2. **Use a simpler model.** Reduce model capacity, remove unhelpful features, or limit a tree's depth.
3. **Regularize.** Add a penalty for large or complex parameter values.
4. **Use early stopping.** Monitor validation loss and stop when it stops improving.
5. **Augment the data.** Create plausible variations, such as slightly shifted or cropped images, when those changes preserve the correct label.

The next example compares polynomial fits with and without regularization:

```python run title="what a penalty does to a wild model"
from sklearn.linear_model import Ridge, Lasso
from sklearn.preprocessing import StandardScaler

for name, reg in [("none  ", LinearRegression()),
                  ("ridge ", Ridge(alpha=1e-3)),
                  ("lasso ", Lasso(alpha=1e-3, max_iter=50_000))]:
    m = make_pipeline(PolynomialFeatures(18), StandardScaler(), reg).fit(X_tr, y_tr)
    coefs = m[-1].coef_
    va = ((m.predict(X_va) - y_va) ** 2).mean()
    print(f"{name}  valid MSE {va:8.4f}   largest |coef| {np.abs(coefs).max():10.2f}   "
          f"nonzero {int((np.abs(coefs) > 1e-6).sum()):2d}/19")
```

The unregularized model needs large positive and negative coefficients to follow the noisy points. A norm penalty makes large coefficients costly. Ridge regularization shrinks coefficients toward zero. Lasso can set some coefficients exactly to zero, which also selects features.

Regularization controls model complexity. Too much can make the model underfit, so compare settings on validation data.

## Read the train-validation gap

Look at training and validation performance together:

```python run title="a diagnostic worth memorising"
baseline = ((y_va - y_tr.mean()) ** 2).mean()      # predict the mean, always

def diagnose(train_err, valid_err, baseline_err):
    # Is the model even beating "predict the mean" on its own training data?
    if train_err > 0.5 * baseline_err:
        return "UNDERFIT   — too rigid; add capacity or features"
    if valid_err > 3 * train_err:
        return "OVERFIT    — regularise, simplify, or get more data"
    return "REASONABLE — now go and improve the features"

print(f"baseline (predict the mean) MSE = {baseline:.3f}\n")
for deg in [1, 4, 18]:
    m = make_pipeline(PolynomialFeatures(deg), LinearRegression()).fit(X_tr, y_tr)
    tr = ((m.predict(X_tr) - y_tr) ** 2).mean()
    va = ((m.predict(X_va) - y_va) ** 2).mean()
    print(f"degree {deg:2d}  train {tr:7.4f}  valid {va:11.4f}  {diagnose(tr, va, baseline)}")
```

- **Both scores are poor:** the model may be too simple, lack useful features, or need more training.
- **Training is good but validation is poor:** the model may be overfitting. Try a simpler model, more data, regularization, or augmentation.
- **Both are good:** the model may be useful. Check for leakage and confirm the evaluation matches deployment.
- **Validation is somewhat better than training:** this can happen with dropout or data augmentation active during training. Check the setup before drawing a conclusion.

A difference between training and validation results is evidence to investigate. It is not a diagnosis by itself.

## A note on modern neural networks

For many small models, test error often falls and then rises as model complexity increases. Some modern deep-learning experiments show a different pattern: test error can fall again after a model becomes large enough to fit the training set. This is often called double descent.

The result depends on the data, model, and training method. It does not remove the need for careful validation. Use validation data to measure the model you actually trained.

## Practice: compare tree depths

Train trees with several maximum depths. Compare their training and validation scores, then compare with a majority-class baseline. If the differences are small relative to cross-validation variation, the data may not distinguish the models.

The example uses cross-validation to check how much the result changes across splits:

```python run
for depth in [1, 3, 5, None]:
    m = DecisionTreeClassifier(max_depth=depth, random_state=0).fit(Xc_tr, yc_tr)
    tr, va = m.score(Xc_tr, yc_tr), m.score(Xc_va, yc_va)
    print(f"depth {str(depth):4s}  train {tr:.3f}  valid {va:.3f}   gap {tr - va:+.3f}")

print(f"\nmajority-class baseline: {max(yc.mean(), 1 - yc.mean()):.3f}")

best = DecisionTreeClassifier(max_depth=3, random_state=0)
s = cross_val_score(best, Xc, yc, cv=5)
print(f"5-fold at depth 3: {s.mean():.3f} ± {s.std():.3f}")
print("folds:", s.round(3))
```

An unrestricted tree can reach perfect training accuracy by memorizing the examples. Its validation score shows whether that fit generalizes.

The baseline gives the score context. If most examples belong to one class, a majority-class predictor may already be strong. Cross-validation variation also matters: when two models differ by less than the split-to-split variation, the available data may not support choosing one over the other.
