A neural network combines linear transformations with nonlinear activations. The activation lets the network represent patterns that a straight line cannot. We will build a small network with NumPy and inspect each part.

## A pattern a line cannot fit

First fit a linear classifier to two crescent-shaped groups:

```python run setup title="two crescents"
import numpy as np, matplotlib.pyplot as plt
from sklearn.datasets import make_moons
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression

X, y = make_moons(n_samples=800, noise=0.22, random_state=0)
X = (X - X.mean(0)) / X.std(0)                    # standardise, always
X_tr, X_va, y_tr, y_va = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)

lin = LogisticRegression().fit(X_tr, y_tr)
print(f"logistic regression, validation accuracy: {lin.score(X_va, y_va):.3f}")
```

The linear model reaches a limit because its decision boundary is a straight line. More training cannot make a straight boundary curve. This is a representation limit, not a training failure.

## Why add an activation?

Stacking linear layers alone does not solve the problem. A composition of linear transformations is still a linear transformation.

```python run title="two linear layers are one linear layer"
rng = np.random.default_rng(0)
W1, W2 = rng.normal(size=(2, 8)), rng.normal(size=(8, 1))

x = rng.normal(size=(4, 2))
two_layers = (x @ W1) @ W2
one_layer  = x @ (W1 @ W2)
print("identical:", np.allclose(two_layers, one_layer))
print("the 'deep' model is really just this 2x1 matrix:\n", (W1 @ W2).round(3).T)
```

Without an activation between layers, a deep stack can be combined into one matrix operation. Adding a nonlinear activation changes what the network can represent.

## Use a nonlinear activation

The rectified linear unit, or ReLU, replaces negative values with zero and leaves positive values unchanged.

```python run title="ReLU"
relu = lambda z: np.maximum(0, z)

z = np.linspace(-3, 3, 200)
plt.figure(figsize=(4.6, 2.4))
plt.plot(z, relu(z)); plt.title("ReLU(z) = max(0, z)")
plt.axhline(0, c="grey", lw=.5); plt.axvline(0, c="grey", lw=.5)
plt.tight_layout()
```

ReLU has gradient 1 for positive inputs and 0 for negative inputs. This can help gradients pass through active units, though it does not solve every gradient problem. Units that receive only negative inputs can stop learning; normalization, initialization, and residual connections also matter in deep networks.

The next example defines a small network with one hidden layer:

```python run title="the forward pass, entire"
def init(n_in, n_hidden, n_out, seed=0):
    rng = np.random.default_rng(seed)
    # He initialisation: variance 2/n_in keeps activations from shrinking layer
    # to layer. The 2 is because ReLU discards half the distribution.
    return {
        "W1": rng.normal(0, np.sqrt(2 / n_in), (n_in, n_hidden)),
        "b1": np.zeros(n_hidden),
        "W2": rng.normal(0, np.sqrt(2 / n_hidden), (n_hidden, n_out)),
        "b2": np.zeros(n_out),
    }

def forward(p, X):
    z1 = X @ p["W1"] + p["b1"]      # (n, hidden)   linear
    a1 = np.maximum(0, z1)          # (n, hidden)   nonlinear
    z2 = a1 @ p["W2"] + p["b2"]     # (n, 1)        linear
    return 1 / (1 + np.exp(-z2))    # (n, 1)        probability

params = init(2, 16, 1)
forward(params, X_tr[:3]).ravel().round(3)
```

The layer multiplies the inputs by weights, adds biases through broadcasting, applies ReLU, then computes an output. This is the forward pass: it turns input values into predictions.

The array shapes must line up through each operation:

```
X   (n, 2)  @  W1 (2, 16)  ->  (n, 16)  + b1 (16,)   broadcast
    (n, 16) @  W2 (16, 1)  ->  (n, 1)   + b2 (1,)    broadcast
```

For matrix multiplication, the inner dimensions must match. The remaining dimensions describe the batch and output features. Checking shapes on paper can help locate errors.

## Estimate gradients numerically

Training needs gradients: how much the loss changes when each parameter changes. We can estimate one by making a small change to a parameter and comparing the losses on either side.

```python run title="numerical gradients"
def loss(p, X, y):
    prob = forward(p, X).ravel()
    prob = np.clip(prob, 1e-9, 1 - 1e-9)
    return -(y * np.log(prob) + (1 - y) * np.log(1 - prob)).mean()

def numerical_grad(p, X, y, eps=1e-5):
    """The definition of a derivative, applied 2x per parameter."""
    grads = {}
    for key, mat in p.items():
        g = np.zeros_like(mat)
        for idx in np.ndindex(mat.shape):
            original = mat[idx]
            mat[idx] = original + eps; hi = loss(p, X, y)
            mat[idx] = original - eps; lo = loss(p, X, y)
            mat[idx] = original
            g[idx] = (hi - lo) / (2 * eps)
        grads[key] = g
    return grads

small = init(2, 4, 1)
g = numerical_grad(small, X_tr[:64], y_tr[:64])
print("dL/dW1 =\n", g["W1"].round(4))
```

This central-difference estimate is useful for checking gradients. It requires two forward passes for every parameter, which becomes expensive for a large network.

```python run title="the cost of brute force"
import time

for hidden in [4, 16, 64]:
    p = init(2, hidden, 1)
    n_params = sum(v.size for v in p.values())
    t = time.perf_counter()
    numerical_grad(p, X_tr[:64], y_tr[:64])
    dt = time.perf_counter() - t
    print(f"hidden={hidden:3d}  {n_params:5d} params  "
          f"{2 * n_params:6d} forward passes  {dt * 1000:8.1f} ms per gradient")
```

The example measures that cost. A model with many parameters would require an impractical number of forward passes for each update. The next chapter derives backpropagation, which calculates all parameter gradients together in a reverse pass through the network.

## Train and inspect the result

For this small network, numerical gradients are still manageable:

```python run title="training with numerical gradients"
p = init(2, 8, 1, seed=1)
sub_X, sub_y = X_tr[:200], y_tr[:200]
history = []
for step in range(60):
    grads = numerical_grad(p, sub_X, sub_y)
    for k in p:
        p[k] -= 0.5 * grads[k]
    history.append(loss(p, sub_X, sub_y))

acc = ((forward(p, X_va).ravel() > 0.5).astype(int) == y_va).mean()
print(f"after 60 brute-force steps: loss {history[-1]:.4f}, validation accuracy {acc:.3f}")
```

The learned boundary curves around the two groups:

```python run title="what it learned"
xx, yy = np.meshgrid(np.linspace(-2.2, 2.4, 220), np.linspace(-2.2, 2.4, 220))
zz = forward(p, np.c_[xx.ravel(), yy.ravel()]).reshape(xx.shape)

fig, ax = plt.subplots(1, 2, figsize=(8.6, 3.2))
ax[0].plot(history); ax[0].set_xlabel("step"); ax[0].set_ylabel("loss")
ax[0].set_title("60 steps, each costing 2x145 forward passes")
ax[1].contourf(xx, yy, zz, levels=20, cmap="coolwarm", alpha=.7)
ax[1].scatter(X_va[:, 0], X_va[:, 1], c=y_va, s=8, cmap="coolwarm", edgecolors="none")
ax[1].set_title("a curved boundary"); ax[1].set_xticks([]); ax[1].set_yticks([])
plt.tight_layout()
```

The network now represents a shape that the linear classifier could not. This example is small and uses numerical gradients only to make the training process visible.

## Why hidden layers can represent many functions

A ReLU unit creates a hinge: its output is flat on one side of a threshold and increases linearly on the other. A weighted sum of hinges can form a piecewise-linear curve.

```python run title="ReLUs are hinges; a sum of hinges is any curve"
grid = np.linspace(-3, 3, 400)
rng2 = np.random.default_rng(4)
W1_, b1_ = rng2.normal(size=(1, 12)) * 3, rng2.normal(size=12) * 2
W2_ = rng2.normal(size=(12, 1))
hidden = np.maximum(0, grid.reshape(-1, 1) @ W1_ + b1_)

fig, ax = plt.subplots(1, 2, figsize=(8.6, 2.9))
ax[0].plot(grid, hidden, lw=.8); ax[0].set_title("12 ReLU units — each a hinge")
ax[1].plot(grid, hidden @ W2_, c="crimson"); ax[1].set_title("their weighted sum")
plt.tight_layout()
```

The universal approximation theorem says that a network with a suitable activation and enough hidden units can approximate a continuous function on a bounded input region. The theorem does not say how many units are needed, how to find their weights, or whether the result will generalize to new data.

## Width, depth, and model size

The next experiment compares networks of different widths and depths:

```python run title="does more help?"
def train(hidden_sizes, steps=400, lr=0.5, seed=0):
    """Analytic gradients — the derivation is tomorrow. Here just to compare shapes."""
    rng = np.random.default_rng(seed)
    sizes = [2, *hidden_sizes, 1]
    Ws = [rng.normal(0, np.sqrt(2 / a), (a, b)) for a, b in zip(sizes, sizes[1:])]
    bs = [np.zeros(b) for b in sizes[1:]]
    for _ in range(steps):
        acts, a = [X_tr], X_tr
        for i, (W, b) in enumerate(zip(Ws, bs)):
            z = a @ W + b
            a = np.maximum(0, z) if i < len(Ws) - 1 else 1 / (1 + np.exp(-z))
            acts.append(a)
        delta = (acts[-1].ravel() - y_tr).reshape(-1, 1) / len(y_tr)
        for i in range(len(Ws) - 1, -1, -1):
            gW, gb = acts[i].T @ delta, delta.sum(0)
            if i > 0:
                delta = (delta @ Ws[i].T) * (acts[i] > 0)
            Ws[i] -= lr * gW; bs[i] -= lr * gb
    a = X_va
    for i, (W, b) in enumerate(zip(Ws, bs)):
        z = a @ W + b
        a = np.maximum(0, z) if i < len(Ws) - 1 else 1 / (1 + np.exp(-z))
    return ((a.ravel() > 0.5).astype(int) == y_va).mean()

for shape in [[2], [8], [32], [128], [16, 16], [16, 16, 16]]:
    print(f"hidden {str(shape):16s}  validation accuracy {train(shape):.3f}")
```

On this task, increasing the network size eventually stops helping. A model needs enough capacity to represent the pattern, but extra parameters do not guarantee better predictions. They also increase memory and compute costs and can make overfitting easier.

The examples below show what happens:

```python run
# 2. All-zero initialisation
def forward_zero(X, hidden=8, steps=200, lr=0.5):
    W1, b1 = np.zeros((2, hidden)), np.zeros(hidden)
    W2, b2 = np.zeros((hidden, 1)), np.zeros(1)
    for _ in range(steps):
        a1 = np.maximum(0, X @ W1 + b1)
        out = 1 / (1 + np.exp(-(a1 @ W2 + b2)))
        d2 = (out.ravel() - y_tr).reshape(-1, 1) / len(y_tr)
        d1 = (d2 @ W2.T) * (a1 > 0)
        W2 -= lr * a1.T @ d2; b2 -= lr * d2.sum(0)
        W1 -= lr * X.T @ d1;  b1 -= lr * d1.sum(0)
    return W1

W1_zero = forward_zero(X_tr)
print("all hidden units identical:", np.allclose(W1_zero, W1_zero[:, :1]))
print("first three columns:\n", W1_zero[:, :3].round(6))

# 3. Initialisation scale
for scale in [1, 10, 50]:
    p = init(2, 64, 1); p["W1"] *= scale
    a1 = np.maximum(0, X_tr @ p["W1"] + p["b1"])
    print(f"scale x{scale:3d}   mean activation {a1.mean():9.3f}   "
          f"dead units {(a1.max(0) == 0).sum():2d}/64")

# 4. Parameter count
p = init(2, 128, 1)
print("\nby hand: 2*128 + 128 + 128*1 + 1 =", 2*128 + 128 + 128*1 + 1)
print("actual  :", sum(v.size for v in p.values()))
```

Without the activation, stacked layers reduce to one linear map, so the network returns to the linear-model result.

If all hidden units start with identical weights and biases, they receive identical gradients and remain identical. Random weight initialization breaks this symmetry. Biases can often start at zero because the different weights already distinguish the units.

Weights that start too large can produce unusually large activations or unstable updates. Initialization methods such as He initialization choose a scale based on the number of inputs, with ReLU's behaviour in mind.

A dense layer with n input values and m output values has n times m weights and m biases. Counting parameters helps estimate memory use and check architecture descriptions.
