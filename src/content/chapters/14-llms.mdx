A causal language model predicts the next token from the tokens before it. Large text collections provide many examples for this task. Later training and software around the model can make it more useful for following instructions.

This chapter follows the process from tokenization to training and text generation. It also covers what the training objective can and cannot tell us about the model's answers.

## Tokens

A language model processes tokens, which are chunks of text. A token may be a whole word, part of a word, punctuation, or another common sequence of characters.

```python run setup title="byte-pair encoding, implemented"
import numpy as np, matplotlib.pyplot as plt
from collections import Counter

def train_bpe(text, n_merges=60):
    """Repeatedly merge the most frequent adjacent pair."""
    tokens = list(text)
    merges = []
    for _ in range(n_merges):
        pairs = Counter(zip(tokens, tokens[1:]))
        if not pairs:
            break
        best, count = pairs.most_common(1)[0]
        if count < 2:
            break
        merged, i = [], 0
        while i < len(tokens):
            if i < len(tokens) - 1 and (tokens[i], tokens[i + 1]) == best:
                merged.append(tokens[i] + tokens[i + 1]); i += 2
            else:
                merged.append(tokens[i]); i += 1
        tokens, _ = merged, merges.append("".join(best))
    return tokens, merges

corpus = """the model predicts the next token, and the next token after that.
a model that predicts well has learned something about the text it read.
the objective is prediction; the capability is a side effect of the objective.
tokens are not words. tokens are whatever the compressor found worth naming.
a token is a unit of text that appeared often enough to deserve its own symbol.
the tokenizer is fitted to a corpus before the model is trained on that corpus.
prediction over trillions of tokens is expensive, and the expense is the point.
the model reads text, the model writes text, and nothing in between is magic.
what the model learns is a distribution over the next token given the previous.
learning a distribution is not the same as learning the truth of a sentence.
"""
tokens, merges = train_bpe(corpus)
print("first merges learned:", merges[:12])
print(f"\n{len(corpus)} characters -> {len(tokens)} tokens "
      f"({len(corpus) / len(tokens):.2f} chars per token)")
```

Byte-pair encoding (BPE) starts with small units and repeatedly joins frequent neighbouring pairs. It builds a vocabulary from patterns in the training text; it does not need a dictionary.

```python run title="what this means in practice"
vocab = sorted(set(tokens), key=len, reverse=True)
print("longest learned tokens:", vocab[:8])
print("\nEnglish is ~4 chars/token. Consequences:")
for label, chars in [("English prose", 4.0), ("code (whitespace)", 2.8),
                     ("rare proper nouns", 1.6), ("non-Latin scripts", 1.2)]:
    print(f"  {label:20s} ~{chars:.1f} chars/token  -> {4.0 / chars:.1f}x the tokens per character")
```

Because tokens are not always words, the same sentence can use different numbers of tokens across languages. Some spellings or numbers may also split in ways that make character counting harder. Token counts affect context length and, in some services, cost.

## Predict the next token

A common training objective gives the model a sequence and asks it to predict the next token at each position.

```python run title="the entire training signal"
words = "the cat sat on the mat and the cat purred".split()
for i in range(1, 6):
    print(f"  context {' '.join(words[:i]):28s} -> predict '{words[i]}'")
```

The next token is already present in the text, so it supplies the training target. This is self-supervised learning: the target is derived from the data. The model learns statistical patterns that help it predict text; this objective does not directly test whether a statement is true.

A simple model can predict the next token using counts from the preceding token:

```python run title="a next-token model, from counts"
def build_bigram(text):
    ws = text.split()
    counts = {}
    for a, b in zip(ws, ws[1:]):
        counts.setdefault(a, Counter())[b] += 1
    return counts

bg = build_bigram(corpus)
print("after 'the', the distribution is:")
for w, c in bg["the"].most_common():
    print(f"   {w:14s} {c / sum(bg['the'].values()):.3f}")
```

This is a language model with very limited context. A transformer uses learned representations and much longer context, but next-token prediction is still a common pretraining objective.

## Generate text

The model produces a score for each possible next token. Softmax converts these scores into probabilities. A decoding rule then selects or samples a token.

Temperature rescales the scores before softmax:

```python run title="temperature, precisely"
def softmax(z, T=1.0):
    z = np.asarray(z, float) / T
    z = z - z.max()
    e = np.exp(z)
    return e / e.sum()

logits = [3.2, 2.9, 2.1, 0.4, -1.0]
labels = ["cat", "dog", "bird", "rock", "xylophone"]

print(f"{'token':12s}" + "".join(f"{f'T={t}':>10s}" for t in [0.2, 0.7, 1.0, 1.5]))
for i, lab in enumerate(labels):
    row = "".join(f"{softmax(logits, t)[i]:10.3f}" for t in [0.2, 0.7, 1.0, 1.5])
    print(f"{lab:12s}{row}")
```

Lower temperatures make the distribution more concentrated; higher temperatures make it flatter.

```python run title="see the distributions"
plt.figure(figsize=(5.6, 3))
for t in [0.2, 0.7, 1.0, 2.0]:
    plt.plot(labels, softmax(logits, t), "o-", label=f"T={t}")
plt.ylabel("probability"); plt.legend(); plt.title("temperature reshapes, it does not re-rank")
plt.tight_layout()
```

For positive temperatures, the ranking of tokens stays the same, while their probabilities change. Greedy decoding always chooses the highest-probability token. Top-k keeps the k most likely tokens. Top-p keeps the smallest set whose probabilities reach a chosen cumulative mass.

Greedy decoding can repeat a phrase because it always chooses the locally most likely next token:

```python run title="greedy decoding gets stuck"
rng = np.random.default_rng(0)

def generate(counts, start, n=14, T=1.0, seed=0):
    r = np.random.default_rng(seed)
    out = [start]
    for _ in range(n):
        nxt = counts.get(out[-1])
        if not nxt:
            break
        opts, cts = zip(*nxt.items())
        p = softmax(np.log(np.array(cts, float)), T)
        out.append(opts[int(np.argmax(p))] if T < 0.05 else opts[r.choice(len(opts), p=p)])
    return " ".join(out)

print("greedy (T→0):", generate(bg, "the", T=0.01))
print("sampled (T=1):", generate(bg, "the", T=1.0))
```

Sampling methods, repetition controls, and stopping rules affect generated text. They do not change the model's learned weights.

## Scaling and compute

Researchers have measured relationships between model loss, data, and compute over a range of experiments. Some early scaling studies found that loss often followed an approximate power-law trend over the tested range.

```python run title="loss falls predictably with compute"
# Illustrative power law of the shape reported by Kaplan et al. (2020)
compute = np.logspace(0, 9, 60)
loss = 2.0 + 12.0 * compute ** -0.08

plt.figure(figsize=(5.4, 3))
plt.loglog(compute, loss)
plt.xlabel("training compute (arbitrary units)"); plt.ylabel("test loss")
plt.title("a straight line on log-log axes, over 9 orders of magnitude")
plt.grid(alpha=.3, which="both"); plt.tight_layout()
```

These relationships can help plan experiments, but they are empirical. They do not guarantee continued improvement at every scale or tell you which model is best for deployment. A larger model costs more to train and serve.

The most compute-efficient training setup may not be the cheapest to serve. Training is often paid once; inference costs recur with use. Choose model size with both costs and the quality target in mind.

## Common training stages

Many language-model development pipelines include several stages:

| Stage | Typical data | Purpose |
|---|---|---|
| Pretraining | large collections of text or other data | Learn broad patterns and representations |
| Supervised fine-tuning | examples of instructions and responses | Improve instruction following and response format |
| Preference tuning | comparisons or feedback on responses | Adjust behaviour to match preferences |

The details vary between models. Preference tuning can use reinforcement learning from human feedback (RLHF) or methods such as direct preference optimization (DPO).

Fine-tuning changes the model's weights and can affect both knowledge and behaviour. Retrieval is often a better fit when answers need to use changing documents or point to specific sources: retrieve relevant material and provide it to the model in context.

## Learn from examples in the prompt

In-context learning means a model can use examples in its prompt without changing its weights.

```python run title="the shape of a few-shot prompt"
prompt = """Translate to French:
sea otter -> loutre de mer
cheese -> fromage
plush giraffe ->"""
print(prompt)
print("\nNo weights changed. The pattern in the context is doing the work.")
```

This makes one pretrained model adaptable to many tasks. The examples still need to be clear, and performance can vary with prompt format and content.

Research has found attention patterns that copy information from earlier tokens in some models. Such mechanisms may help explain parts of in-context learning, but they are not a complete explanation of the capability.

## Limits and practical checks

A language model's next-token objective rewards plausible continuations. A plausible answer can still be wrong, so fluency is not evidence of accuracy.

The model's weights reflect its training data and training time. A model may have outdated or incomplete information. Provide current sources or connect it to tools when the task depends on recent facts.

The model also has a context limit. Long inputs can cost more and may be used unevenly. Test whether important information remains available where the model needs it.

When building with language models:

- Validate outputs that affect important decisions.
- Constrain output formats and check them in code.
- Use retrieval for source-based answers.
- Keep exact arithmetic and fixed rules in ordinary code.
- Treat uncertain output as uncertain; a confident tone is not a confidence score.

For top-p sampling, sort tokens by probability, keep the shortest prefix whose cumulative probability reaches p, renormalize, then sample from that subset.

```python run
lo, hi = 0.05, 20.0
for _ in range(50):
    mid = (lo + hi) / 2
    if softmax(logits, mid)[3] < 0.05: lo = mid
    else: hi = mid
print(f"'rock' crosses 5% at T = {hi:.3f}   (p = {softmax(logits, hi)[3]:.4f})")

def top_p_sample(logits, p=0.9, T=1.0, seed=0):
    probs = softmax(logits, T)
    order = np.argsort(probs)[::-1]
    cum = np.cumsum(probs[order])
    keep = order[:np.searchsorted(cum, p) + 1]
    renorm = probs[keep] / probs[keep].sum()
    return int(np.random.default_rng(seed).choice(keep, p=renorm)), keep

for p in [0.5, 0.9, 0.99]:
    _, keep = top_p_sample(logits, p=p)
    print(f"top-p {p}: keeps {len(keep)} tokens -> {[labels[i] for i in keep]}")
```

Temperature and top-p interact: flattening the distribution can increase the number of tokens included in the nucleus. Change one setting at a time and compare the generated output.
