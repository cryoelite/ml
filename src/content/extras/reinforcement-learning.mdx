In supervised learning, examples include an input and a target answer. In reinforcement learning (RL), an agent takes actions and receives rewards from an environment. It must learn which actions lead to good outcomes, sometimes after many steps.

## The basic loop

The agent observes a state, chooses an action, receives a reward, and sees a new state. Rewards may be delayed, so the agent must work out which earlier actions contributed to the result. This is called credit assignment.

The agent also generates its own experience. Changing its policy changes which situations it sees, so training data is not fixed as it is in ordinary supervised learning.

## Core terms

- **State** ($s$): information the agent observes about the current situation.
- **Action** ($a$): a choice available to the agent.
- **Reward** ($r$): feedback from the environment.
- **Policy** ($\pi$): a rule for choosing actions.
- **Value** ($V$ or $Q$): an estimate of future rewards from a state or state-action pair.

This example uses a small corridor with a reward at each end.

```python run setup title="a tiny world"
import numpy as np

# A 1-D corridor. Start in the middle, +1 for reaching the right end,
# -1 for the left end. Every other step gives nothing.
N_STATES = 7
GOAL, TRAP = N_STATES - 1, 0

def step(s, a):
    """a = 0 (left) or 1 (right). Returns (next_state, reward, done)."""
    s2 = max(0, min(N_STATES - 1, s + (1 if a else -1)))
    if s2 == GOAL:  return s2, 1.0, True
    if s2 == TRAP:  return s2, -1.0, True
    return s2, 0.0, False

print("states:", list(range(N_STATES)), " start: 3  goal: 6  trap: 0")
print("reward is zero everywhere except the two ends —")
print("so the agent must connect an action at state 3 to an outcome three steps later.")
```

## Future rewards and discounting

A reward received later is often multiplied by a discount factor $\gamma$:

$$
G_t = r_t + \gamma r_{t+1} + \gamma^2 r_{t+2} + \dots
$$

A lower discount puts more weight on near-term rewards. Discounting can also help keep the total finite in tasks that continue indefinitely.

```python run title="what gamma does to your horizon"
for g in [0.5, 0.9, 0.99]:
    horizon = 1 / (1 - g)
    print(f"gamma {g:.2f}: reward {20} steps away is worth {g ** 20:.4f} now"
          f"   (effective horizon ~{horizon:.0f} steps)")
```

## Q-learning

Q-learning estimates the value of taking each action in each state. It updates an estimate toward the immediate reward plus the best estimated future value:

$$
Q(s,a) \leftarrow Q(s,a) + \alpha\left[r + \gamma\max_{a'}Q(s',a') - Q(s,a)\right]
$$

The difference inside the brackets is the temporal-difference error.

```python run title="Q-learning, entire"
def q_learn(episodes=500, alpha=0.1, gamma=0.95, eps=0.2, seed=0, max_steps=50):
    rng = np.random.default_rng(seed)
    Q = np.zeros((N_STATES, 2))
    for _ in range(episodes):
        s, done, t = 3, False, 0
        # A purely greedy agent can cycle between two states forever, so every
        # real RL loop caps the episode length. This is not a detail you can skip.
        while not done and t < max_steps:
            a = rng.integers(2) if rng.random() < eps else int(Q[s].argmax())
            s2, r, done = step(s, a)
            target = r + (0 if done else gamma * Q[s2].max())
            Q[s, a] += alpha * (target - Q[s, a])      # the whole algorithm
            s, t = s2, t + 1
    return Q

Q = q_learn()
print(f"{'state':>6s} {'Q(left)':>9s} {'Q(right)':>10s}  best")
for s in range(1, N_STATES - 1):
    print(f"{s:6d} {Q[s,0]:9.3f} {Q[s,1]:10.3f}  {'right' if Q[s].argmax() else 'left'}")
```

In this small environment the table can represent every state and action. The agent uses some random actions while learning, so it can discover rewards it has not reached yet.

## Bootstrapping

Q-learning’s target includes an estimate of future reward. Learning from an estimate that is itself still changing is called bootstrapping.

```python run title="truth propagating backwards from the goal"
for n in [1, 3, 10, 50, 300]:
    Q_n = q_learn(episodes=n, seed=1)
    vals = " ".join(f"{Q_n[s].max():6.3f}" for s in range(1, N_STATES - 1))
    print(f"after {n:3d} episodes:  {vals}")
print("\nstates near the goal (right) learn first, then it flows leftward")
```

The observed reward anchors the update to experience. Over time, information about a reward can affect estimates for earlier states. The method can be effective, but its behavior depends on the environment and learning setup.

## Exploration and exploitation

An agent must balance exploring unfamiliar actions with using the best action it currently knows. An epsilon-greedy policy chooses randomly with probability epsilon and otherwise chooses its current favourite.

```python run title="the cost of not exploring"
for eps in [0.0, 0.05, 0.2, 0.8]:
    Q_e = q_learn(episodes=300, eps=eps, seed=3)
    reached = Q_e[3].max() > 0.1
    print(f"eps={eps:.2f}  value at start state {Q_e[3].max():7.4f}  "
          f"{'found the goal' if reached else 'NEVER found the goal'}")
```

Too little exploration can leave the agent with a poor policy. Too much exploration can waste experience. Other exploration strategies include optimism bonuses and Thompson sampling.

## From tables to neural networks

A table is too large for tasks with many states, such as board games or image inputs. Deep Q-networks use a neural network to estimate action values. Experience replay and a separate target network can help make training more stable, but neural-network RL remains sensitive to design choices.

Combining bootstrapping, function approximation, and off-policy learning can create instability. This combination is often called the “deadly triad”; it is a warning about a difficult setting, not a claim that every such method will diverge.

## Policy gradients and language models

Policy-gradient methods adjust the policy directly. In simplified form, they increase the probability of actions that received higher returns.

```python run title="REINFORCE, on a two-armed bandit"
def reinforce(steps=800, lr=0.1, seed=0):
    rng = np.random.default_rng(seed)
    true_reward = [0.3, 0.7]          # arm 1 is better; the agent doesn't know
    theta = 0.0                       # logit for choosing arm 1
    for _ in range(steps):
        p1 = 1 / (1 + np.exp(-theta))
        a = int(rng.random() < p1)
        r = float(rng.random() < true_reward[a])
        # grad of log pi(a) w.r.t. theta  ->  (a - p1)
        theta += lr * (a - p1) * r
    return 1 / (1 + np.exp(-theta))

print(f"probability of choosing the better arm: {reinforce():.3f}")
print("no value function anywhere — just 'do more of what worked'")
```

Preference-based training for language models can use a related setup: collect comparisons, train a reward model to predict preferences, then update the model policy to score well under that reward. Methods and training recipes vary. Since the reward model is only a proxy for human preferences, a policy can learn to exploit its mistakes.

## What to expect from RL

- It can require many environment interactions.
- Results may vary across random seeds and training runs.
- Reward design is difficult; a poorly chosen reward can lead to unwanted behavior.
- Real-world experiments may be costly or unsafe, so simulation is common.
- Simulation results may not transfer cleanly to the real environment.

Evaluate with multiple runs and scenarios, and compare with simple baselines. If the task can be expressed as supervised learning or direct optimisation, those approaches may need much less interaction.
