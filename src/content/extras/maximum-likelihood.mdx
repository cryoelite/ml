A loss measures how well a model predicts the data. Maximum likelihood gives a common way to choose model parameters: prefer parameters that assign higher probability to the observations.

## The principle

Suppose a model assigns probability $p_\theta(y_i \mid x_i)$ to each observed outcome. If the observations are conditionally independent, the likelihood of the dataset is:

$$
\mathcal{L}(\theta) = \prod_{i=1}^{n} p_\theta(y_i \mid x_i)
$$

Maximum likelihood chooses parameters that maximise this product.

Products of many small probabilities can underflow numerically, so we work with the log-likelihood instead.

```python run title="why nobody optimises the product"
import numpy as np

for n in [500, 1_100]:
    probs = np.full(n, 0.5)         # n coin-flip-ish predictions
    print(f"{n:5,d} factors   product {np.prod(probs):.3e}   log-sum {np.log(probs).sum():9.1f}")

print("\nAt 1,100 the product is exactly 0.0 — the likelihood is gone, and no")
print("optimiser can recover a gradient from it. The log-sum is unbothered.")
```

The logarithm turns the product into a sum and preserves which parameters give the maximum:

$$
\log \mathcal{L}(\theta) = \sum_{i=1}^{n} \log p_\theta(y_i \mid x_i)
$$

Optimisers usually minimise, so we take the negative. This is the negative log-likelihood, or NLL.

## Squared error comes from a Gaussian noise model

Assume each target equals the model prediction plus independent Gaussian noise:

$$
y_i = f_\theta(x_i) + \varepsilon_i, \qquad \varepsilon_i \sim \mathcal{N}(0, \sigma^2)
$$

Taking the negative log-likelihood gives squared error, up to constants that do not depend on the model parameters.

This assumption is useful when errors are roughly symmetric and outliers are not too common. It also explains why squared error reacts strongly to large errors.

```python run title="watch the assumption break"
rng = np.random.default_rng(0)
x = np.linspace(0, 10, 40)
y = 2.0 * x + 1.0 + rng.normal(0, 1.0, 40)
y_bad = y.copy(); y_bad[20] += 60          # one mis-keyed value

def fit_mse(x, y):
    X = np.column_stack([np.ones(len(x)), x])
    return np.linalg.solve(X.T @ X, X.T @ y)

def fit_mae(x, y, steps=8000, lr=0.01):
    """Minimise |error| instead — the Laplace assumption."""
    w = np.zeros(2); X = np.column_stack([np.ones(len(x)), x])
    for _ in range(steps):
        w -= lr * (X.T @ np.sign(X @ w - y)) / len(y)
    return w

print("truth              slope 2.00  intercept 1.00")
print(f"MSE, clean data    slope {fit_mse(x, y)[1]:.2f}  intercept {fit_mse(x, y)[0]:.2f}")
print(f"MSE, one outlier   slope {fit_mse(x, y_bad)[1]:.2f}  intercept {fit_mse(x, y_bad)[0]:.2f}")
print(f"MAE, one outlier   slope {fit_mae(x, y_bad)[1]:.2f}  intercept {fit_mae(x, y_bad)[0]:.2f}")
```

A single extreme value can move a squared-error fit more than an absolute-error fit. Absolute error corresponds to a Laplace noise model, which is more tolerant of large deviations.

## Cross-entropy comes from a Bernoulli model

For a binary target, let the model predict probability p of class 1. The probability of observing y is:

$$
p(y \mid x) = \hat{p}^{\,y}(1 - \hat{p})^{1-y}
$$

Taking the negative log gives binary cross-entropy:

$$
-\log \mathcal{L}(\theta) = -\sum_i \left[y_i\log\hat{p}_i + (1-y_i)\log(1-\hat{p}_i)\right]
$$

The same recipe gives squared error under a Gaussian assumption and cross-entropy under a Bernoulli assumption.

```python run title="the two derivations, side by side"
def nll_gaussian(y, mu, sigma=1.0):
    return ((y - mu) ** 2 / (2 * sigma ** 2)).mean()

def nll_bernoulli(y, p):
    p = np.clip(p, 1e-12, 1 - 1e-12)
    return -(y * np.log(p) + (1 - y) * np.log(1 - p)).mean()

print("Gaussian assumption -> squared error")
print("  ", round(nll_gaussian(np.array([1.0, 0.0]), np.array([0.9, 0.2])), 4))
print("Bernoulli assumption -> cross-entropy")
print("  ", round(nll_bernoulli(np.array([1.0, 0.0]), np.array([0.9, 0.2])), 4))
print("\nsame recipe, different assumed noise model")
```

## Multiple classes and softmax

For k classes, the model needs a probability for each class, with all probabilities summing to one. Softmax converts logits into such probabilities:

<M id="softmax">softmax</M>

$$
\hat{p}_j = \frac{e^{z_j}}{\sum_m e^{z_m}}
$$

For a labelled example, categorical cross-entropy is the negative log probability assigned to the correct class.

```python run title="cross-entropy is the negative log of one number"
logits = np.array([2.0, 1.0, 0.1])
true = 0

probs = np.exp(logits - logits.max()); probs /= probs.sum()
print("softmax probs   :", probs.round(4))
print("loss (long way) :", round(-np.log(probs[true]), 4))
print("loss (stable)   :", round(-logits[true] + logits.max()
                                 + np.log(np.exp(logits - logits.max()).sum()), 4))
print("\nonly the true class's probability appears. the rest matter only")
print("through the denominator, which is what makes them compete.")
```

The code uses the log-sum-exp calculation, which is more numerically stable than exponentiating large logits directly. That is why libraries such as PyTorch expect logits as input to cross-entropy loss rather than probabilities that you have already passed through softmax.

## Choose a loss that fits the target

The same method can derive losses for other data types. For example, a Poisson distribution can model counts with a non-negative rate.

$$
p(y \mid \lambda) = \frac{\lambda^y e^{-\lambda}}{y!}
$$

Ignoring the term that does not depend on the model gives a loss of $\lambda - y\log\lambda$.

```python run title="Poisson loss, derived and used"
rng = np.random.default_rng(1)
x = rng.uniform(0, 4, 300)
counts = rng.poisson(np.exp(0.4 + 0.5 * x))     # true log-rate is linear in x

def fit_poisson(x, y, steps=3000, lr=0.05):
    """Model log(rate) as linear. Loss = lambda - y*log(lambda)."""
    w = np.zeros(2); X = np.column_stack([np.ones(len(x)), x])
    for _ in range(steps):
        lam = np.exp(X @ w)
        w -= lr * (X.T @ (lam - y)) / len(y)     # gradient of the Poisson NLL
    return w

w = fit_poisson(x, counts)
w_mse = np.linalg.solve(np.column_stack([np.ones(len(x)), x]).T @ np.column_stack([np.ones(len(x)), x]),
                        np.column_stack([np.ones(len(x)), x]).T @ counts)
print(f"truth:            log-rate = 0.40 + 0.50x")
print(f"Poisson fit:      log-rate = {w[0]:.2f} + {w[1]:.2f}x")
print(f"\nnaive MSE fit on raw counts: {w_mse[0]:.2f} + {w_mse[1]:.2f}x")
print("(which models the count directly, and will happily predict negatives)")
print("MSE prediction at x=0:", round(w_mse[0], 2),
      " Poisson prediction at x=0:", round(np.exp(w[0]), 2))
```

The right loss depends on what the target represents and what assumptions fit the data. Common examples include:

| Target | Example assumption | Common loss |
|---|---|---|
| Real value with symmetric noise | Gaussian | Squared error |
| Real value with heavier tails | Laplace | Absolute error |
| Binary outcome | Bernoulli | Binary cross-entropy |
| One of several classes | Categorical | Cross-entropy |
| Count | Poisson | Poisson negative log-likelihood |

Treat this table as a starting point. Check the model’s assumptions and the evaluation metric for your task. A loss always makes assumptions about the data, even when you use a library default.
