Course datasets are tidy so you can focus on models. Real datasets need inspection before training. This guide covers duplicates, missing values, inconsistent categories, dates, and leakage.

## Start by looking at the data

This small dataset includes common problems: inconsistent labels, missing values, unusual numeric values, and repeated rows.

```python run setup title="a realistically awful dataset"
import numpy as np, pandas as pd

rng = np.random.default_rng(0)
n = 500
df = pd.DataFrame({
    "user_id":   rng.integers(1000, 1100, n),
    "signup":    pd.to_datetime("2024-01-01") + pd.to_timedelta(rng.integers(0, 400, n), "D"),
    "plan":      rng.choice(["free", "pro", "Pro", "PRO ", "enterprise", None], n,
                            p=[.4, .2, .1, .05, .2, .05]),
    "monthly_spend": rng.lognormal(3, 1, n).round(2),
    "sessions":  rng.poisson(12, n).astype(float),
    "country":   rng.choice(["DE", "de", "US", "GB", "  US", None], n,
                            p=[.3, .1, .3, .2, .05, .05]),
    "churned":   rng.integers(0, 2, n),
})
# the things real data does to you
df.loc[rng.choice(n, 40, replace=False), "sessions"] = np.nan
df.loc[rng.choice(n, 12, replace=False), "monthly_spend"] = -1     # sentinel for "unknown"
df.loc[rng.choice(n, 8, replace=False), "monthly_spend"] = 999999  # test accounts
df = pd.concat([df, df.iloc[:20]], ignore_index=True)              # duplicated rows

print(df.shape)
df.head(6)
```

Before training, check its size, missing values, numeric ranges, category spellings, and duplicates.

```python run title="the four-line first look"
print("shape:", df.shape, " duplicated rows:", df.duplicated().sum())
print("\nnulls per column:\n", df.isna().sum()[df.isna().sum() > 0].to_string())
print("\nnumeric summary:\n", df[["monthly_spend", "sessions"]].describe().round(1).to_string())
print("\nplan values:", df["plan"].value_counts(dropna=False).to_dict())
```

The summaries reveal duplicated rows, missing values, unusual spending values, and several spellings of the same plan. These issues can distort training or evaluation if you leave them unexplained.

## 1. Find duplicate rows and entities

```python run title="duplicates leak across the split"
print("exact duplicate rows :", df.duplicated().sum())
print("duplicate user_ids   :", df["user_id"].duplicated().sum())
clean = df.drop_duplicates().reset_index(drop=True)
print(f"\n{len(df)} -> {len(clean)} rows")
```

Exact duplicate rows can usually be removed. Repeated people or other entities need more care. If the same person appears in both training and validation, the validation score may be too optimistic. Split by the entity when the task requires predictions for new entities.

## 2. Check sentinel values

Some datasets use special numbers such as -1 to mean “unknown.” These values are still treated as numbers unless you replace them.

```python run title="-1 is not a small number"
spend = clean["monthly_spend"]
print(f"with sentinels    mean {spend.mean():10.2f}  median {spend.median():8.2f}")
real = spend[(spend >= 0) & (spend < 100_000)]
print(f"sentinels removed mean {real.mean():10.2f}  median {real.median():8.2f}")
print(f"\n{(spend < 0).sum()} rows of -1 (means 'unknown')")
print(f"{(spend > 100_000).sum()} rows of 999999 (test accounts)")
```

Compare summaries, then confirm the meaning with the data source. Convert known sentinel values to missing values rather than assuming they represent real amounts.

```python run title="make the unknown actually unknown"
clean["monthly_spend"] = clean["monthly_spend"].replace({-1: np.nan, 999999: np.nan})
print("nulls in monthly_spend now:", clean["monthly_spend"].isna().sum())
```

## 3. Standardise category values

Differences in case and whitespace can turn one category into several.

```python run title="normalise before you encode"
print("before:", sorted(clean["plan"].dropna().unique()))
clean["plan"] = clean["plan"].str.strip().str.lower()
clean["country"] = clean["country"].str.strip().str.upper()
print("after :", sorted(clean["plan"].dropna().unique()))
print("country:", sorted(clean["country"].dropna().unique()))
```

Clean category text before encoding it. Apply the same transformation during training and prediction. Better still, put the transformation in a shared pipeline so the two paths cannot silently diverge.

## 4. Understand missing values

Missingness may itself carry information.

```python run title="the missingness is itself a signal"
clean["sessions_missing"] = clean["sessions"].isna().astype(int)
by = clean.groupby("sessions_missing")["churned"].agg(["mean", "count"])
print(by.round(3).to_string())
print("\nif those churn rates differ, 'missing' carries information")
print("and imputing it away throws that information out.")
```

You can drop rows, fill missing values, or add an indicator showing that a value was missing. The right choice depends on why the data is missing and how much is missing. Learn fill values from the training set only; using the full dataset leaks information into evaluation.

Some tree libraries can handle missing values directly. Check the behavior of the library and model you use.

## 5. Treat time as part of the data

```python run title="the temporal sanity checks"
print("date range:", clean["signup"].min().date(), "to", clean["signup"].max().date())
print("rows per month:")
print(clean.groupby(clean["signup"].dt.to_period("M")).size().tail(6).to_string())
```

Check time zones, impossible dates, gaps, and incomplete recent periods. If you predict future outcomes, split by time so later information does not leak into training.

## A reusable preparation pipeline

A shared function can apply transformations that do not learn from the data, such as trimming spaces and replacing known sentinels.

```python run title="one function, both paths"
def prepare(raw: pd.DataFrame) -> pd.DataFrame:
    """Every transformation that must happen identically in training and serving.

    Deliberately contains NO fitted state — no means, no encoders, no vocabularies.
    Those must be learned on train and applied, which is what a scikit-learn
    Pipeline is for. Keeping the two kinds of step apart is what stops leakage.
    """
    out = raw.copy()
    out = out.drop_duplicates()
    out["plan"] = out["plan"].str.strip().str.lower()
    out["country"] = out["country"].str.strip().str.upper()
    out["monthly_spend"] = out["monthly_spend"].replace({-1: np.nan, 999999: np.nan})
    out["sessions_missing"] = out["sessions"].isna().astype(int)
    return out.reset_index(drop=True)

prepared = prepare(df)
print(f"{len(df)} raw rows -> {len(prepared)} prepared")
print("plan values:", sorted(prepared["plan"].dropna().unique()))
print("spend range:", round(prepared['monthly_spend'].min(), 2),
      "to", round(prepared['monthly_spend'].max(), 2))
```

Fitted transformations are different. Imputation values, category vocabularies, and scaling statistics must be learned on the training split and then applied to validation or production data. A scikit-learn pipeline keeps those steps together.

```python run title="fitted state belongs in a Pipeline"
from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import OneHotEncoder, StandardScaler
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.model_selection import train_test_split

num = ["monthly_spend", "sessions", "sessions_missing"]
cat = ["plan", "country"]

pipe = Pipeline([
    ("prep", ColumnTransformer([
        ("num", Pipeline([("impute", SimpleImputer(strategy="median")),
                          ("scale", StandardScaler())]), num),
        ("cat", OneHotEncoder(handle_unknown="ignore", min_frequency=5), cat),
    ])),
    ("model", HistGradientBoostingClassifier(random_state=0)),
])

X = prepared[num + cat]
y = prepared["churned"]
Xtr, Xva, ytr, yva = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)
pipe.fit(Xtr, ytr)
print(f"validation accuracy {pipe.score(Xva, yva):.3f}")
print(f"majority baseline   {max(yva.mean(), 1 - yva.mean()):.3f}")
print("\n(the labels here are random, so there is no signal to find — a flexible")
print(" model lands at or slightly BELOW the trivial baseline, which is the")
print(" correct outcome and exactly what chapter 6 predicts)")
```

The labels in this example are random, so a model should not discover a useful pattern. Compare its score with a simple baseline. A result below baseline can be a sign that the data contains no predictive signal.

The pipeline’s unknown-category setting handles categories absent from training, and its minimum-frequency setting can group rare categories. Choose these settings based on the dataset and task.

## A practical checklist

1. Check the number of rows, duplicate rows, and missing values.
2. Review numeric ranges for impossible values and special codes.
3. Inspect category values for spelling and whitespace variants.
4. Check date ranges, gaps, and incomplete periods.
5. Ask whether each feature would be available when making a prediction.
6. Look at the target across key features and groups.
7. Read a sample of complete rows.
8. Split by the right unit: person, time, location, or another group.
9. Fit imputation, encoding, and scaling on training data only.
10. Use the same preparation logic for training and prediction.

A few real rows can reveal errors that summary statistics miss. Inspecting them is a quick, useful habit.
