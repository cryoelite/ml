Information theory gives a useful language for prediction. It connects probability, surprise, entropy, and the cross-entropy loss used in classification and language modelling.

## Surprise

An unlikely event is more surprising than an expected one. The information in an event with probability p is:

$$
I(p) = -\log_2 p \quad \text{bits}
$$

```python run setup title="surprise, quantified"
import numpy as np, matplotlib.pyplot as plt

for p, label in [(1.0, "certain"), (0.5, "a coin flip"), (0.25, "one of four"),
                 (0.01, "a 1-in-100 event"), (1/1024, "one of 1024")]:
    bits = -np.log2(p) + 0.0                 # + 0.0 turns -0.0 into 0.0
    print(f"P = {p:8.5f}  ({label:16s}) -> {bits:6.2f} bits of information")
```

A certain event gives zero bits because it provides no new information. One outcome among 1,024 equally likely outcomes gives 10 bits. The logarithm also makes information add across independent events.

## Entropy: average surprise

Entropy is the average information in a distribution:

$$
H(p) = -\sum_i p_i \log_2 p_i
$$

```python run title="entropy across distributions"
def entropy(p):
    p = np.asarray(p, float); p = p[p > 0]
    return -(p * np.log2(p)).sum()

cases = {
    "fair coin":            [0.5, 0.5],
    "biased coin (0.9)":    [0.9, 0.1],
    "certain":              [1.0, 0.0],
    "fair 8-sided die":     [1/8] * 8,
    "skewed 8 outcomes":    [0.9] + [0.1/7] * 7,
}
for name, p in cases.items():
    print(f"{name:22s} {entropy(p):6.3f} bits")
```

A fair coin has one bit of entropy. A certain outcome has zero. For a known distribution, entropy describes the minimum average code length needed in the ideal limit.

## Cross-entropy: predictions from a model

Suppose the true outcomes follow distribution p, while your model predicts q. Cross-entropy is the average cost of using q to encode outcomes from p:

$$
H(p, q) = -\sum_i p_i \log q_i
$$

```python run title="the cost of being wrong about the distribution"
truth = np.array([0.7, 0.2, 0.1])

print(f"true entropy (best possible)     : {entropy(truth):.4f} bits\n")
print(f"{'your belief q':>28s} {'cross-entropy':>14s} {'excess':>9s}")
for name, q in {
    "exactly right":      [0.7, 0.2, 0.1],
    "slightly off":       [0.6, 0.25, 0.15],
    "quite wrong":        [0.2, 0.3, 0.5],
    "uniform (no idea)":  [1/3, 1/3, 1/3],
}.items():
    q = np.array(q)
    ce = -(truth * np.log2(q)).sum()
    print(f"{name:>28s} {ce:14.4f} {ce - entropy(truth):9.4f}")
```

Cross-entropy is minimised when the model’s probabilities match the target distribution. Its minimum is the entropy of the data; prediction error adds a further cost.

## KL divergence

The extra cost is the Kullback–Leibler divergence:

$$
D_{KL}(p \parallel q) = H(p, q) - H(p) = \sum_i p_i \log\frac{p_i}{q_i}
$$

```python run title="cross-entropy = entropy + KL"
def kl(p, q):
    p, q = np.asarray(p, float), np.asarray(q, float)
    m = p > 0
    return (p[m] * np.log2(p[m] / q[m])).sum()

q = np.array([0.2, 0.3, 0.5])
print(f"H(p)        = {entropy(truth):.4f}")
print(f"D_KL(p||q)  = {kl(truth, q):.4f}")
print(f"sum         = {entropy(truth) + kl(truth, q):.4f}")
print(f"H(p, q)     = {-(truth * np.log2(q)).sum():.4f}   <- the same number")
```

KL divergence is zero when the distributions match and positive otherwise. It is not symmetric: swapping p and q can change the result.

For a fixed data distribution p, minimising cross-entropy over q is equivalent to minimising this KL divergence, because H(p) does not depend on the model.

## Perplexity

Language-model papers often report perplexity rather than cross-entropy. If loss is measured in nats, perplexity is the exponential of the loss. If it is measured in bits, use two to the power of the loss.

```python run title="what a perplexity number means"
print(f"{'loss (nats)':>12s} {'perplexity':>12s}   interpretation")
for loss in [np.log(50000), 5.0, 3.0, 2.0, 1.5]:
    print(f"{loss:12.3f} {np.exp(loss):12.1f}   "
          f"as unsure as picking uniformly among {np.exp(loss):.0f} tokens")
```

Perplexity can be read as an effective number of choices at each position. Lower is better when comparing models on the same data, tokenisation, and evaluation setup. Numbers from different datasets or tokenisers may not be directly comparable.

## Prediction and compression

A probability model can be used to encode data: common events need fewer bits, and rare events need more. Under ideal arithmetic coding, the expected code length is tied to cross-entropy.

```python run title="the loss is the file size"
# The bigram model's cross-entropy on its own corpus, read as bits per character.
text = ("the quick brown fox jumps over the lazy dog " * 40 +
        "pack my box with five dozen liquor jugs " * 40)

counts = {}
for a, b in zip(text, text[1:]):
    counts.setdefault(a, {}); counts[a][b] = counts[a].get(b, 0) + 1

total_bits = 0.0
for a, b in zip(text, text[1:]):
    row = counts[a]; n = sum(row.values())
    total_bits += -np.log2(row[b] / n)

bits_per_char = total_bits / (len(text) - 1)
print(f"raw ASCII                 : 8.00 bits/char")
print(f"under this bigram model   : {bits_per_char:.2f} bits/char")
print(f"implied compression ratio : {8 / bits_per_char:.1f}x")
print(f"\n{len(text)} chars -> {total_bits / 8:.0f} bytes at the model's own loss")
```

This links prediction and compression mathematically. Better probability estimates can make shorter encodings. Compression alone, however, does not prove that a model understands the content.

## Terms you will see

| Term | Meaning | Common use |
|---|---|---|
| Entropy | Average surprise in a distribution | Decision trees and information limits |
| Cross-entropy | Cost of predictions against a target distribution | Classification and language-model loss |
| KL divergence | Difference between distributions, with direction | Variational methods and distillation |
| Perplexity | Exponential of language-model loss | Language-model evaluation |
| Mutual information | How much one variable tells us about another | Feature and representation analysis |

These quantities appear in many parts of machine learning. The practical question is often simple: what distribution is the model predicting, and what does its loss measure?
