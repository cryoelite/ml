A model can run without errors and still learn the wrong thing. Check the data, labels, loss, gradients, baseline, and split before tuning more parameters.

## 1. Can the model fit ten examples?

Try to overfit a tiny batch. A small network should be able to memorise ten examples.

```python run local setup title="the first test, always"
import torch, torch.nn as nn, numpy as np

torch.manual_seed(0)
X = torch.randn(10, 4)
y = torch.randint(0, 3, (10,))          # 10 examples, 3 classes

model = nn.Sequential(nn.Linear(4, 32), nn.ReLU(), nn.Linear(32, 3))
opt = torch.optim.AdamW(model.parameters(), lr=1e-2)
loss_fn = nn.CrossEntropyLoss()

for step in range(300):
    opt.zero_grad()
    loss = loss_fn(model(X), y)
    loss.backward(); opt.step()
    if step % 100 == 99:
        acc = (model(X).argmax(1) == y).float().mean()
        print(f"step {step+1:3d}  loss {loss.item():.5f}  train accuracy {acc:.0%}")
```

Success does not show that the model generalises. It shows that the forward pass, loss, gradients, and optimiser can work together.

If it fails, check that the optimiser sees the model parameters, gradients are enabled, labels match inputs, the loss uses the model output, and you call the optimiser steps correctly. Also look for accidental gradient detachment or disabled gradient tracking.

## 2. Check the starting loss

With zero logits and k classes, cross-entropy is ln(k). This is a useful reference for a uniform prediction.

```python run local title="the loss you should see before training"
for k in [2, 3, 10, 1000]:
    print(f"{k:5d} classes -> untrained cross-entropy should be ln({k}) = {np.log(k):.4f}")

logits = torch.zeros(500, 10)
labels = torch.randint(0, 10, (500,))
print("\nmeasured with 10 classes and zero logits:",
      round(nn.CrossEntropyLoss()(logits, labels).item(), 4))
```

An unexpected starting loss can point to incorrect labels, shapes, or outputs. For regression, compare the model’s error with a simple baseline and check the target scale.

## 3. Print tensor shapes

Some shape mismatches broadcast without raising an error.

```python run local title="shapes, and the silent broadcast"
pred = torch.randn(32, 1)      # what nn.Linear(h, 1) gives you
targ = torch.randn(32)         # what your labels look like

print("pred", tuple(pred.shape), " targ", tuple(targ.shape))
print("difference broadcasts to", tuple((pred - targ).shape), "<- 1024 numbers, not 32")
print("\nMSE on the broadcast   :", round(((pred - targ) ** 2).mean().item(), 4))
print("MSE done correctly     :", round(((pred.squeeze() - targ) ** 2).mean().item(), 4))
```

The prediction and label shapes should match the loss function’s expectations. Print both before training.

## 4. Inspect the actual inputs

Check the tensors that enter the model, not only the source file.

```python run local title="check the batch, not the dataframe"
batch = torch.randn(64, 4) * 50 + 200      # pretend: unstandardised features

print(f"min {batch.min():8.2f}  max {batch.max():8.2f}  "
      f"mean {batch.mean():7.2f}  std {batch.std():6.2f}")
print("nan:", torch.isnan(batch).any().item(), " inf:", torch.isinf(batch).any().item())

scaled = (batch - batch.mean(0)) / batch.std(0)
print(f"\nafter standardising: mean {scaled.mean():.3f}  std {scaled.std():.3f}")
print("inputs should be roughly mean 0, std 1 — chapter 5's ravine problem")
```

Look for values on very different scales, NaNs, infinities, labels outside the allowed range, and examples that do not look as expected. Visualise a few inputs when possible.

## 5. Inspect gradients

```python run local title="gradient norms tell you where the problem is"
torch.manual_seed(0)
deep = nn.Sequential(*[layer for i in range(6)
                       for layer in (nn.Linear(16, 16), nn.Sigmoid())])
x = torch.randn(32, 16)
loss = deep(x).pow(2).mean()
loss.backward()

print("gradient norm by layer (input side first):")
for i, m in enumerate(deep):
    if isinstance(m, nn.Linear):
        print(f"  layer {i//2}: {m.weight.grad.norm().item():.3e}")
print("\nsigmoid stack: the gradient shrinks toward the input. chapter 9's plot,")
print("in a live model, in three lines.")
```

Gradients that are all zero may mean the graph is disconnected. Gradients that shrink across layers can indicate vanishing gradients; very large or non-finite values can indicate instability. Use the numbers as clues, then inspect the relevant layers and loss.

## 6. Compare with a simple baseline

```python run local title="is it beating nothing?"
y_true = torch.randint(0, 2, (1000,))
majority = (y_true.float().mean() > 0.5).float()
print(f"class balance          : {y_true.float().mean():.1%} positive")
print(f"always-majority accuracy: {(y_true == majority.long()).float().mean():.1%}")
print("\nany model that doesn't beat this has learned nothing, whatever its loss curve did")
```

A model that does not beat a suitable baseline may not be learning useful signal. Pick a baseline that matches the task, such as predicting the majority class or the mean target.

## 7. Tune only after these checks

If the data and training path look right, try changing the learning rate first. Then investigate model capacity and regularisation based on the training and validation scores. Change one thing at a time so you can tell what helped.

The order matters because a parameter search cannot repair a broken data pipeline or misaligned labels. Debug those first.

## A small sanity check

This function combines several inexpensive checks into one place.

```python run local title="a reusable sanity harness"
def sanity_check(model, batch_x, batch_y, loss_fn, n_classes=None):
    """Run before every serious training run. Cheap, and catches most of it."""
    issues = []

    if torch.isnan(batch_x).any() or torch.isinf(batch_x).any():
        issues.append("inputs contain nan or inf")
    if abs(batch_x.mean().item()) > 3 or not (0.2 < batch_x.std().item() < 5):
        issues.append(f"inputs poorly scaled (mean {batch_x.mean():.2f}, "
                      f"std {batch_x.std():.2f})")

    out = model(batch_x)
    if out.shape[0] != batch_y.shape[0]:
        issues.append(f"batch mismatch: output {tuple(out.shape)} vs "
                      f"labels {tuple(batch_y.shape)}")
    if n_classes and (batch_y.min() < 0 or batch_y.max() >= n_classes):
        issues.append(f"labels out of range for {n_classes} classes")

    loss = loss_fn(out, batch_y)
    if n_classes:
        expected = np.log(n_classes)
        if not (0.5 * expected < loss.item() < 2 * expected):
            issues.append(f"initial loss {loss.item():.3f}, expected ~{expected:.3f}")

    loss.backward()
    dead = [n for n, p in model.named_parameters()
            if p.grad is None or p.grad.abs().max() == 0]
    if dead:
        issues.append(f"no gradient reaching: {dead[:3]}")

    model.zero_grad()
    return issues or ["all checks passed"]

torch.manual_seed(0)
m = nn.Sequential(nn.Linear(4, 16), nn.ReLU(), nn.Linear(16, 3))
for line in sanity_check(m, torch.randn(64, 4), torch.randint(0, 3, (64,)),
                         nn.CrossEntropyLoss(), n_classes=3):
    print(" *", line)
```

Adapt the thresholds and checks to your data. A sanity check is a starting point for investigation, not a proof that a training run is correct.
