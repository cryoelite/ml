Bayesian methods represent uncertainty with probability distributions. They are useful when data is limited, when prior knowledge matters, or when the cost of a poorly understood prediction is high.

## The basic idea

A frequentist model estimates a fixed parameter from data. A Bayesian model represents uncertainty about that parameter and updates it as evidence arrives.

<M id="bayes-rule">Bayes' rule</M> describes the update:

$$
\underbrace{p(\theta \mid D)}_{\text{posterior}} \propto
\underbrace{p(D \mid \theta)}_{\text{likelihood}} \cdot
\underbrace{p(\theta)}_{\text{prior}}
$$

The likelihood describes how well a parameter explains the data. The prior describes what was plausible before seeing the data. Their combination gives the posterior: what is plausible after seeing it.

This example tracks our estimate of a coin’s probability of heads as we observe more flips.

```python run setup title="watching a belief update"
import numpy as np, matplotlib.pyplot as plt

# Estimating a coin's bias. Prior: Beta(2,2) — "probably fairish, not certain".
grid = np.linspace(0, 1, 400)

def beta_pdf(x, a, b):
    from math import lgamma
    logc = lgamma(a + b) - lgamma(a) - lgamma(b)
    return np.exp(logc + (a - 1) * np.log(np.clip(x, 1e-12, 1))
                  + (b - 1) * np.log(np.clip(1 - x, 1e-12, 1)))

rng = np.random.default_rng(0)
flips = (rng.random(200) < 0.7).astype(int)     # a coin that lands heads 70%

plt.figure(figsize=(5.6, 3.4))
for n in [0, 1, 5, 20, 200]:
    heads = flips[:n].sum()
    # Beta is conjugate to Bernoulli: the posterior is just Beta(2+heads, 2+tails)
    plt.plot(grid, beta_pdf(grid, 2 + heads, 2 + (n - heads)),
             label=f"after {n} flips")
plt.axvline(0.7, ls=":", c="k", lw=1)
plt.xlabel("P(heads)"); plt.ylabel("belief density"); plt.legend(fontsize=7)
plt.tight_layout()

for n in [1, 5, 20, 200]:
    h = flips[:n].sum(); a, b = 2 + h, 2 + n - h
    mean = a / (a + b); sd = np.sqrt(a * b / ((a + b) ** 2 * (a + b + 1)))
    print(f"after {n:3d} flips: estimate {mean:.3f} ± {sd:.3f}")
```

With only a few flips, many values remain plausible. As more data arrives, the estimate narrows around the observed rate. The width of the distribution shows uncertainty alongside the estimate.

## Priors and regularisation

A prior can encode useful knowledge, such as a probability lying between zero and one or an effect usually being small. It also affects results when data is scarce. Different priors can produce different conclusions, so state the assumptions and check whether reasonable alternatives change the result.

This example compares several priors on the same coin data.

```python run title="the prior matters when data is scarce, and stops when it isn't"
print(f"{'prior':>26s} {'after 5 flips':>15s} {'after 200':>12s}")
for name, (a0, b0) in {
    "uniform: Beta(1,1)": (1, 1),
    "gently fair: Beta(2,2)": (2, 2),
    "strongly fair: Beta(50,50)": (50, 50),
    "wrong: Beta(1,20)": (1, 20),
}.items():
    row = []
    for n in [5, 200]:
        h = flips[:n].sum()
        row.append((a0 + h) / (a0 + b0 + n))
    print(f"{name:>26s} {row[0]:15.3f} {row[1]:12.3f}")
print("\ntrue value 0.700 — after 200 flips even the badly wrong prior has been overruled")
```

As the sample grows, the data has more influence. With limited data, the prior can have a noticeable effect.

Some regularised objectives also have a Bayesian interpretation. For example, maximising a likelihood with a Gaussian prior on weights is equivalent to minimising a loss with an L2 penalty. This equivalence depends on the model and prior assumptions; regularisation in general is not automatically Bayesian.

## Gaussian processes

A Gaussian process puts a probability distribution over functions. It can make predictions together with an uncertainty estimate, based on its kernel and the observed data.

This small example fits a Gaussian process with a radial basis function kernel.

```python run title="a model that widens where it has no data"
def rbf(a, b, length=1.0):
    return np.exp(-0.5 * (a[:, None] - b[None, :]) ** 2 / length ** 2)

X_train = np.array([-3.0, -2.0, -1.5, 1.5, 2.0, 3.0])
y_train = np.sin(X_train) + rng.normal(0, 0.1, len(X_train))
X_test = np.linspace(-5, 5, 300)

noise = 0.01
K = rbf(X_train, X_train) + noise * np.eye(len(X_train))
Ks, Kss = rbf(X_train, X_test), rbf(X_test, X_test)
alpha = np.linalg.solve(K, y_train)
mean = Ks.T @ alpha
var = np.clip(np.diag(Kss) - np.sum(Ks * np.linalg.solve(K, Ks), axis=0), 0, None)
sd = np.sqrt(var)

plt.figure(figsize=(5.8, 3.4))
plt.fill_between(X_test, mean - 2 * sd, mean + 2 * sd, alpha=0.22, label="±2 sd")
plt.plot(X_test, mean, label="mean prediction")
plt.plot(X_test, np.sin(X_test), "k:", lw=1, label="truth")
plt.scatter(X_train, y_train, c="crimson", s=28, zorder=5, label="data")
plt.legend(fontsize=7); plt.tight_layout()

print(f"uncertainty near a data point (x=2.0) : {sd[np.argmin(abs(X_test - 2.0))]:.3f}")
print(f"uncertainty in the gap     (x=0.0)    : {sd[np.argmin(abs(X_test - 0.0))]:.3f}")
print(f"uncertainty extrapolating  (x=5.0)    : {sd[-1]:.3f}")
```

The uncertainty is usually lower near observed points and higher in less supported regions. Its behavior depends on the chosen kernel and noise assumptions. It is a useful warning about extrapolation, not a guarantee that every model knows when it is wrong.

Exact Gaussian process fitting requires operations on an n-by-n matrix and often scales roughly as n cubed. That makes it practical for smaller datasets, while large datasets need approximations or other methods.

## Where Bayesian methods help

- **Bayesian optimisation:** choose promising settings when each experiment is expensive.
- **Sequential experiments:** update conclusions as new observations arrive.
- **Small datasets:** combine limited evidence with explicit domain knowledge.
- **High-cost errors:** represent uncertainty as one part of a larger safety process.

Bayesian methods also appear inside modern machine learning. Monte Carlo dropout and deep ensembles can provide useful uncertainty signals, though they are approximations and need evaluation. Variational autoencoders use variational inference to approximate distributions that are difficult to compute directly.

## The useful takeaway

A point prediction does not tell you how uncertain the model is. Ask how uncertainty was measured, whether it was calibrated for the task, and what happens when the input differs from the training data. Bayesian methods provide one principled way to answer those questions; they are not the only one.
