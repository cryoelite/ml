A model can make errors for different reasons. It may be too simple to capture a pattern, too sensitive to the particular training sample, or limited by noise in the data. The bias–variance decomposition gives names to these sources for squared-error regression.

## The setup

Assume the observed target is a true function plus zero-mean noise:

$$
y = f(x) + \varepsilon, \qquad \mathbb{E}[\varepsilon] = 0, \quad \mathrm{Var}(\varepsilon) = \sigma^2
$$

Imagine fitting the same learning procedure on many training sets drawn from the same process. At a fixed input, expected squared error can be split into three terms:

$$
\mathbb{E}\big[(y - \hat{f}(x_0))^2\big] =
\underbrace{\big(\mathbb{E}[\hat{f}(x_0)] - f(x_0)\big)^2}_{\text{bias}^2} +
\underbrace{\mathbb{E}\big[(\hat{f}(x_0) - \mathbb{E}[\hat{f}(x_0)])^2\big]}_{\text{variance}} +
\underbrace{\sigma^2}_{\text{irreducible}}
$$

- **Bias squared:** how far the average fitted model is from the true function.
- **Variance:** how much fitted predictions change across training sets.
- **Noise:** variation in the targets that the inputs cannot explain under these assumptions.

## Where the terms come from

<Reveal title="A short derivation" kind="math">

Let $\bar f = \mathbb{E}[\hat f(x_0)]$. Add and subtract $\bar f$ inside the error:

$$
\mathbb{E}\big[(f + \varepsilon - \hat f)^2\big]
=
\mathbb{E}\big[((f-\bar f)+ (\bar f-\hat f)+\varepsilon)^2\big]
$$

After expanding, the cross-terms have expectation zero when the noise is independent, has mean zero, and the model estimates are averaged over training sets. What remains is bias squared, variance, and noise.

This exact decomposition is for squared error under the stated assumptions. Other losses need different analyses.
</Reveal>

## Measure them in a small experiment

Here we know the data-generating function, so we can fit the same procedure on many samples and estimate the terms.

```python run setup title="fit the same method 200 times"
import numpy as np, matplotlib.pyplot as plt
from sklearn.preprocessing import PolynomialFeatures
from sklearn.linear_model import LinearRegression
from sklearn.pipeline import make_pipeline

TRUE_SIGMA = 0.35
def truth(x):
    return np.sin(1.9 * np.pi * x)

def sample(n, rng):
    x = rng.uniform(0, 1, n)
    return x, truth(x) + rng.normal(0, TRUE_SIGMA, n)

def decompose(degree, n_train=25, n_fits=200, seed=0):
    """Fit the same procedure on many datasets; measure bias, variance, noise."""
    rng = np.random.default_rng(seed)
    x_test = np.linspace(0.02, 0.98, 120)
    preds = np.zeros((n_fits, len(x_test)))
    for i in range(n_fits):
        xt, yt = sample(n_train, rng)
        m = make_pipeline(PolynomialFeatures(degree), LinearRegression())
        m.fit(xt.reshape(-1, 1), yt)
        preds[i] = m.predict(x_test.reshape(-1, 1))

    mean_pred = preds.mean(0)
    bias2 = ((mean_pred - truth(x_test)) ** 2).mean()
    variance = preds.var(0).mean()
    return bias2, variance, TRUE_SIGMA ** 2, x_test, preds, mean_pred

print(f"{'degree':>7s} {'bias^2':>9s} {'variance':>10s} {'noise':>8s} {'total':>9s}")
for deg in [1, 2, 3, 5, 8, 12]:
    b, v, s, *_ = decompose(deg)
    print(f"{deg:7d} {b:9.4f} {v:10.4f} {s:8.4f} {b + v + s:9.4f}")
```

As polynomial degree increases, bias can fall because the model can represent more patterns. Variance can rise because the fit responds more to the specific sample. Noise stays fixed. The balance can produce a middle range with lower total error.

```python run title="the classic picture"
degs = range(1, 14)
rows = [decompose(d)[:3] for d in degs]
b = [r[0] for r in rows]; v = [r[1] for r in rows]; s = [r[2] for r in rows]
tot = [x + y + z for x, y, z in zip(b, v, s)]

plt.figure(figsize=(5.6, 3.4))
plt.plot(degs, b, "o-", label="bias²")
plt.plot(degs, v, "s-", label="variance")
plt.plot(degs, s, ":", label="irreducible noise")
plt.plot(degs, tot, "k-", lw=2, label="total error")
plt.axvline(degs[int(np.argmin(tot))], ls="--", c="grey", lw=1)
plt.yscale("log"); plt.xlabel("polynomial degree"); plt.ylabel("error (log)")
plt.legend(fontsize=8); plt.tight_layout()
print(f"minimum total error at degree {degs[int(np.argmin(tot))]}")
```

The next plot shows three examples. A simple model can miss the shape in a consistent way. A flexible model can vary a lot across samples. A middle-sized model may balance those errors for this setup.

```python run title="high bias and high variance, drawn"
fig, ax = plt.subplots(1, 3, figsize=(10, 3))
for a, deg in zip(ax, [1, 4, 12]):
    _, _, _, xt, preds, mean_pred = decompose(deg)
    for i in range(40):

    a.plot(xt, truth(xt), "k--", lw=1.6, label="truth")
    a.plot(xt, mean_pred, c="crimson", lw=1.8, label="average fit")

    a.set_xticks([]); a.set_yticks([])
ax[0].legend(fontsize=7)
plt.tight_layout()
```

## Averaging and ensembles

When several models make different errors, averaging can reduce variance. Bagging uses this idea to improve unstable learners such as decision trees. Boosting instead adds models in sequence, often correcting errors the current ensemble still makes. These descriptions are useful intuition; the exact effects depend on the data and training choices.

## There is a noise floor

The true function cannot predict random noise added after the input is observed.

```python run title="how good could any model possibly be?"
rng = np.random.default_rng(7)
x, y = sample(4000, rng)

perfect = ((y - truth(x)) ** 2).mean()          # the true function, no fitting
print(f"error of the TRUE function on noisy data : {perfect:.4f}")
print(f"the noise variance we injected           : {TRUE_SIGMA ** 2:.4f}")
print()
for deg in [3, 5, 8]:
    b, v, s, *_ = decompose(deg, n_train=25)
    print(f"degree {deg:2d} total error {b + v + s:.4f}   "
          f"({(b + v) / s:.1f}x the floor)")
```

In real work, the true function and noise level are unknown. Human disagreement on labels, conflicting labels for duplicate inputs, and careful error analysis can help estimate how much uncertainty comes from the data itself.

Do not treat one estimate of a “Bayes error” as a guaranteed ceiling. It depends on the target definition, available inputs, and assumptions about the data.

## A useful caveat

The familiar bias–variance picture is often drawn as a U-shaped curve as model capacity grows. Modern over-parameterised models can show double descent, where error rises and then falls again. The decomposition still applies in its setting; a simple monotonic relationship between model size and variance does not always apply.

## What to do with the idea

| Symptom | Possible cause | Things to try |
|---|---|---|
| Training and validation scores are both poor | Model or features may be too limited | Improve features, choose a more suitable model, or train longer |
| Training is strong but validation is much worse | Model may be sensitive to the sample | Gather more data, regularise, or average models |
| Results plateau despite model changes | Labels or inputs may limit performance | Review labels, improve measurement, or reconsider the target |

Use the decomposition to form hypotheses about error, then test them on held-out data. It is an intuition tool, not a substitute for evaluation.
