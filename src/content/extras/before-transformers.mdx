Before transformers, language models used word counts and recurrent networks. The ideas from those systems still appear in modern papers and software.

## N-grams: count what came before

An n-gram model counts which token tends to follow a short context. For example, a bigram looks at one previous word, while a trigram looks at two.

```python run setup title="an n-gram language model"
import numpy as np
from collections import Counter, defaultdict

text = """the cat sat on the mat the cat sat on the floor the dog sat on the mat
the dog ran to the park the cat ran to the mat the cat slept on the floor"""
words = text.split()

def ngram_model(words, n):
    counts = defaultdict(Counter)
    for i in range(len(words) - n + 1):
        context, nxt = tuple(words[i:i + n - 1]), words[i + n - 1]
        counts[context][nxt] += 1
    return counts

for n in [2, 3]:
    m = ngram_model(words, n)
    ctx = ("the",) if n == 2 else ("the", "cat")
    total = sum(m[ctx].values())
    print(f"{n}-gram, after {' '.join(ctx)!r}:",
          {w: round(c / total, 2) for w, c in m[ctx].most_common(3)})
```

The goal is familiar: estimate a distribution over the next token. The simple model stores observed counts.

As the context grows, possible contexts grow quickly. Many will not appear in a small dataset.

```python run title="why n-grams stop at about n=5"
vocab = 50_000
print(f"{'n':>3s} {'possible contexts':>22s}")
for n in [2, 3, 4, 5, 6]:
    print(f"{n:3d} {vocab ** (n - 1):22,d}")
print("\nEnglish has maybe 10^12 words ever written. At n=5 there are 10^18")
print("possible contexts, so essentially every context you meet is unseen.")
```

A zero count can give an ordinary phrase zero probability. Smoothing methods, such as Kneser–Ney, reserve probability for unseen cases. But counting alone does not let similar contexts share much evidence: “the cat sat” and “the dog sat” are separate keys.

Neural language models helped by representing words and contexts so related examples could share information.

## Recurrent neural networks

A recurrent neural network (RNN) reads a sequence one item at a time. It updates a hidden state at each step and passes that state to the next step.

```python run title="an RNN cell, and what it does to a signal"
def rnn_forward(inputs, W_x, W_h, b, h0):
    h, states = h0, []
    for x in inputs:
        h = np.tanh(x @ W_x + h @ W_h + b)
        states.append(h.copy())
    return np.array(states)

rng = np.random.default_rng(0)
T, d_in, d_h = 20, 4, 6
seq = rng.normal(size=(T, d_in))
W_x, W_h, b = rng.normal(size=(d_in, d_h)) * .5, rng.normal(size=(d_h, d_h)) * .5, np.zeros(d_h)

states = rnn_forward(seq, W_x, W_h, b, np.zeros(d_h))
print("hidden state at t=0 :", states[0].round(2))
print("hidden state at t=19:", states[-1].round(2))
print("\nevery output depends on every previous input, through h")
```

The same weights are reused at every step, so parameter count does not grow with sequence length. The state also supports inputs of different lengths.

Training an RNN over many steps can be difficult. Backpropagation through time multiplies gradients by a sequence of per-step derivatives. If those factors are small, information about early steps can fade; if they are large, gradients can grow.

```python run title="the gradient to early timesteps, measured"
def gradient_reaching_step_zero(T, radius, dim=8, seed=0):
    """Chain the per-step Jacobians and measure what survives.

    This is exactly what backpropagation-through-time computes: the gradient
    arriving at step 0 is a product of T Jacobians, one per timestep.
    """
    r = np.random.default_rng(seed)
    Wh = r.normal(size=(dim, dim))
    Wh *= radius / max(abs(np.linalg.eigvals(Wh)))     # set the spectral radius
    xs = r.normal(size=(T, dim)) * 0.1
    h, J = np.zeros(dim), np.eye(dim)
    for x in xs:
        h = np.tanh(x + h @ Wh)
        J = (np.diag(1 - h ** 2) @ Wh.T) @ J           # one more Jacobian in the chain
    return np.linalg.norm(J, 2)

print(f"{'steps back':>11s} {'radius 0.5':>13s} {'radius 0.9':>13s}")
for T in [1, 5, 10, 20, 40, 80]:
    print(f"{T:11d} {gradient_reaching_step_zero(T, 0.5):13.2e} "
          f"{gradient_reaching_step_zero(T, 0.9):13.2e}")
```

This example shows how the signal changes in one small setup. The result depends on the weights, inputs, and activation; it illustrates the problem, not a fixed limit on every RNN.

## LSTMs: a gated memory

Long short-term memory networks (LSTMs) add a cell state and gates. The gates control what information to keep, add, and expose.

```python run title="an LSTM cell, all four gates"
def sigmoid(z): return 1 / (1 + np.exp(-z))

def lstm_step(x, h, c, P):
    z = np.concatenate([x, h])
    f = sigmoid(z @ P["Wf"] + P["bf"])      # forget: what to erase from c
    i = sigmoid(z @ P["Wi"] + P["bi"])      # input:  how much new to write
    g = np.tanh(z @ P["Wg"] + P["bg"])      # candidate content
    o = sigmoid(z @ P["Wo"] + P["bo"])      # output: what to expose as h
    c = f * c + i * g                       # <- the highway
    h = o * np.tanh(c)
    return h, c

d = 8
r = np.random.default_rng(0)
P = {k: (r.normal(size=(d + d, d)) * .3 if k.startswith("W") else np.zeros(d))
     for k in ["Wf", "bf", "Wi", "bi", "Wg", "bg", "Wo", "bo"]}
P["bf"] = np.ones(d)      # the classic trick: bias the forget gate OPEN at init

h, c = np.zeros(d), np.zeros(d)
for t in range(30):
    h, c = lstm_step(r.normal(size=d) * 0.1, h, c, P)
print("cell state magnitude after 30 steps:", round(float(np.abs(c).mean()), 3))
print("(a plain RNN's state would have collapsed toward zero by now)")
```

The cell state can carry information forward along a path with fewer repeated transformations. This can help gradients travel across longer sequences, although it does not make every long-range dependency easy to learn.

The gate biases can affect early behavior. For example, a positive forget-gate bias can encourage the cell to retain information at the start of training.

## Sequence-to-sequence models

For tasks such as translation, an encoder can read the source sequence and a decoder can generate the target. Early sequence-to-sequence models compressed the source into one context vector. That fixed-size summary could be a bottleneck for long inputs.

```python run title="the bottleneck, sized"
for length, d_h in [(5, 256), (20, 256), (50, 256), (100, 256)]:
    print(f"source of {length:3d} tokens -> one vector of {d_h} numbers"
          f"   ({d_h / length:6.1f} numbers per token)")
print("\nEvery word of a 100-token sentence has to survive in 256 numbers,")
print("and the first word passed through 100 updates to get there.")
```

Attention addressed this by letting the decoder use information from different encoder positions at each output step.

```python run title="attention as it was first used"
def softmax(z):
    z = z - z.max(); e = np.exp(z); return e / e.sum()

encoder_states = rng.normal(size=(6, 8))     # one per source token
decoder_state  = rng.normal(size=8)          # where the decoder is now

scores = encoder_states @ decoder_state      # relevance of each source position
weights = softmax(scores)
context = weights @ encoder_states           # a DIFFERENT context vector each step

print("attention over 6 source tokens:", weights.round(3))
print("sums to", round(float(weights.sum()), 6))
print("\nno fixed bottleneck: the context is rebuilt for every output token")
```

The decoder can now build a context suited to the token it is generating. The first attention methods were added to recurrent models. The 2017 Transformer paper showed that attention could instead be the central sequence operation.

## Ideas that remain useful

- **Encoder and decoder:** still common terms for systems that map one sequence to another.
- **Teacher forcing:** train a decoder with the correct previous token. At prediction time it must use its own output, so the two settings differ.
- **Beam search:** keep several likely partial sequences rather than choosing only one at every step.
- **Recurrence:** still useful when sequential state updates suit the task or hardware. Newer recurrent designs aim to train efficiently in parallel.

The historical lesson is practical: an idea can be useful but limited by its training cost or hardware. New methods often change the trade-offs rather than erase the older ideas.
